# 网申控件经验系统与 Agent 执行优化计划

> 更新说明（2026-09-19）：交通银行完整实测证明全页快照、短命 UID 和逐层组件操作是当前主要成本。本文的控件目录、配方和合成评测继续有效；浏览器观察、输入协议和执行层后续由[《Resume Browser MCP：局部观察与事务式表单执行改进计划》](resume-browser-mcp-plan.md)接管。本文中“只使用官方原始工具、不增加表单工具”的旧决策不再适用于下一阶段。

> 状态：阶段 0–2 与确定性评测已完成；独立 Agent 对照和经验库决策门待后续数据
> 目标版本：Resume Companion 0.12.0 及后续增量版本
> 当前基线：Resume Companion 0.11.1 / `chrome-devtools-mcp` 1.9.0
> 日期：2026-09-19
> 适用范围：本地资料 MCP、`resume-autofill` skill、合成招聘网站与评测工具

## 1. 决策

Resume Companion 继续采用“本地资料 MCP + 官方 Chrome DevTools MCP + Agent 组合调用”的主架构，不恢复浏览器扩展、Native Host、自研 CDP 驱动或站点专用浏览器协议。

下一阶段不再优先增加浏览器原子工具，而是建立四类可复用资产：

1. **控件经验目录**：记录真实网申中反复出现的控件类型、识别信号、依赖关系和常见失败方式。
2. **Agent 交互配方**：规定每类控件的观察、操作、等待、验证和恢复顺序，使用官方 Chrome DevTools MCP 的稳定工具执行。
3. **合成验收与评测集**：把竞品代码暴露出的复杂情况复刻成本地虚构页面，持续测量成功率、调用次数、耗时和边界违规。
4. **本地经验库**：在静态配方经过验证后，保存本机实际成功的站点语义映射和配方使用结果，减少跨任务重复推理。

截图属于观察和诊断能力，不是日常执行方式。正常填写继续使用页面快照、UID 和 `fill_form`；局部截图只在语义分组、遮挡或纯视觉信息无法通过快照表达时使用。首版不启用坐标点击。

商业插件发布包仅作为静态研究材料。生产代码不复制其混淆 bundle，不调用其后端接口，也不导入未经验证的站点选择器。

## 2. 问题与现状

### 2.1 当前能力已经足够完成任务

0.11.1 已验证：

- 一次 `fill_form(includeSnapshot=true)` 可以批量填写文本、多行文本、原生下拉、复选框和单选框。
- 通用 UID、点击、等待和快照可以完成三级异步学校级联、月份控件和普通记录保存。
- Network、Console、局部截图和定点只读脚本可以解释疑难失败。
- 专用持久 Chrome Profile 可以跨任务保留登录和站点状态。
- 最终提交仍由用户完成，自动测试中的最终提交计数保持为 0。

当前普通 20 控件热运行 P50 为 4.429 秒；12 个复选框一次批量填写 P50 为 2.816 秒。浏览器底座具备可用性能，端到端体验更容易被以下问题拖慢：

- Agent 对同一种复杂控件反复重新探索。
- 没有先划分依赖边界，导致本可批量的字段被拆成多个工具回合。
- 动态弹层出现后重复获取整页快照，或使用固定等待时间盲试。
- 批量部分成功后整批重放，而不是只补缺失项。
- 长页面包含大量与当前章节无关的信息。
- 不同任务之间没有保存经过验证的页面经验。

### 2.2 竞品代码能够提供什么

本地静态研究材料包括塔塔网申 0.8.3、牛客网申助手 1.0.8 和求职方舟 2026.9.18 的浏览器发布包。第一轮分析确认三者都采用混合架构：

| 来源 | 可提炼经验 | 无法直接获得的资产 |
| --- | --- | --- |
| 塔塔网申 | 大量组件触发器、站点识别、截图与 DOM 联合匹配、选项匹配、增量补填 | 云端页面配置、长期字段映射、服务端匹配模型 |
| 牛客网申助手 | 页面裁剪、平台选择器缓存、配置有效性检查、AI 配置兜底、组件库适配 | 远端选择器全量历史、线上匹配结果、用户运行数据 |
| 求职方舟 | DOM 语义抽取、MutationObserver 弹层观察、字段和值分层推理、少量平台适配 | 模型服务、服务端提示词、线上站点经验和成功统计 |

这些材料可以直接减少问题发现、方案设计和测试构造的成本，但不能作为可直接接入官方 Chrome DevTools MCP 的生产实现。

### 2.3 需要分开的四个问题

后续设计必须把以下层次分开，避免再次陷入“专用解析还是原子操作”的二选一：

| 层次 | 回答的问题 | 默认实现 |
| --- | --- | --- |
| 观察 | 当前有哪些字段、候选、章节和错误？ | 快照；必要时定点脚本、Network、Console、局部截图 |
| 规划 | 哪个资料字段对应哪个网页字段，先后依赖是什么？ | Agent + skill +资料 source ref +经验提示 |
| 执行 | 怎样可靠操作这个控件？ | `fill_form` 快车道；复杂控件使用 UID 原子工具配方 |
| 验证与恢复 | 操作是否成功，失败后从哪里继续？ | 动作附带快照、页面回显、增量补填和有限诊断 |

## 3. 目标与非目标

### 3.1 目标

- 普通字段优先在一个依赖批次内完成，减少模型和 MCP 往返。
- Agent 第一次遇到常见复杂控件时即可获得成熟操作顺序，不从零盲试。
- 同一种组件在不同网站复用同一配方，避免按域名维护大量脚本。
- 把竞品出现过的边缘情况转成可重复、可统计的本地验收。
- 每次失败都能归入明确类别，并有停止条件和下一步。
- 真实使用积累的成功经验只保存在本机，并可随页面变化自动降级。
- 所有新增产品代码继续使用严格 TypeScript。

### 3.2 非目标

- 不承诺首轮覆盖所有招聘网站和所有自定义组件。
- 不为每个域名建立长期硬编码选择器仓库。
- 不直接复制或重新打包商业插件前端代码。
- 不重放招聘网站写 API，不绕过页面校验、验证码或最终提交。
- 不让截图成为普通页面的默认观察，也不启用坐标点击。
- 不在缺少基线数据时提前构建复杂的自动学习或规则评分系统。
- 不把站点经验和真实简历事实混存在同一资料文件中。

## 4. 目标架构

```text
用户请求与选定资料 revision
              ↓
resume-autofill skill
├── 页面规划与依赖分层
├── 控件经验目录
├── 交互配方与恢复规则
└── 安全边界与完成报告
        ↓                    ↓
Resume Companion MCP     Chrome DevTools MCP
本地资料与未来经验查询      快照 / fill_form / click / fill / wait
        ↓                    ↓
版本化本地 JSON          专用持久 Chrome Profile
                             ↓
                   合成表单或真实招聘网站
                             ↓
                   验证结果与本地经验反馈
```

### 4.1 三条执行通道

#### 快速通道

适用于互不依赖的可见文本输入、多行文本、原生下拉、复选框和单选框：

```text
一次页面快照
→ 读取本页需要的资料栏目
→ 按依赖边界组成 fill_form 批次
→ 使用 includeSnapshot 返回的新快照核对
→ 只补缺失或错误字段
```

#### 复杂控件通道

适用于搜索下拉、级联、树选择、日期范围、虚拟列表、弹窗和重复经历。Agent 选择一个控件配方，并按配方的小步边界调用官方工具。配方不保存临时 UID，不假设网页选择器永远稳定。

#### 诊断通道

只有当前两条通道无法解释失败时进入。针对一个具体问题选择一种最相关能力，并遵守现有诊断预算：

- 属性、约束或真实节点不清楚：定点只读脚本。
- 异步候选、服务端校验或保存异常：相关 Network 请求。
- 怀疑页面脚本故障：相关 Console 信息。
- 视觉分组、遮挡或纯图标语义不清楚：指定 UID 或当前视口局部截图。

## 5. 控件经验目录

### 5.1 首批控件家族

第一轮至少整理以下家族：

1. 原生文本框与多行文本。
2. 原生 select、checkbox 和 radio group。
3. 非搜索自定义下拉。
4. 异步搜索 combobox。
5. 多级 cascader。
6. tree select 与可展开树节点。
7. 年、月、日和普通日期选择器。
8. 日期范围与“至今”。
9. 弹窗候选选择器。
10. 虚拟滚动或分页候选列表。
11. 重复教育、工作、项目记录的添加和编辑。
12. 折叠、懒加载和滚动后才出现的章节。
13. iframe 内表单。
14. contenteditable 与富文本区域。
15. 自动保存、前端校验与服务端校验状态。

首批目录来源为竞品静态代码和现有交通银行调试经历。来源用于追溯问题类型，不直接成为生产依赖。

### 5.2 配方格式

每个配方使用一致结构编写：

```yaml
id: async-search-combobox
family: searchable_select
recognition:
  semantic_roles: [combobox, listbox, option]
  observable_signals: [可输入搜索词, 点击后出现候选层]
preconditions:
  - 控件可见且未禁用
  - 目标值来自明确资料或用户指令
plan:
  - 打开控件并复用动作返回快照
  - 找到当前弹层中的搜索输入
  - 输入最小必要关键词
  - 等待候选层变化或明确无结果
  - 只从页面展示候选中选择
verification:
  - 控件回显等于目标语义
  - 相关校验错误消失
fallbacks:
  - 重新观察当前弹层
  - 检查只读属性或相关请求
stop_conditions:
  - 没有可信候选
  - 多个候选无法区分
  - 页面要求用户验证
```

实际 reference 使用 Markdown 表达，YAML 仅展示字段语义。配方必须说明：

- 识别信号和不适用条件。
- 哪些步骤会改变 DOM，从而使旧 UID 失效。
- 可以批量的动作和必须逐步执行的动作。
- 等待的是文本、候选集合、结构变化还是回显。
- 成功证据、部分成功状态和恢复起点。
- 何时停止并交给用户。

### 5.3 配方选择原则

- 先按语义角色和可观察行为选择配方，再参考框架 class 名。
- 组件库名称只能作为提示，不作为唯一判断依据。
- 域名专用提示必须经过真实页面验证，并始终重新观察当前状态。
- 一个问题同时匹配多个配方时，优先选择动作面更小、验证条件更明确的配方。
- 配方失败后最多更换一次同类配方，再进入诊断或人工接管。

## 6. 页面规划与调用优化

### 6.1 依赖分层

Agent 在写入前把当前页字段划分为：

- **L0 独立字段**：写入不会改变其他字段结构，可进入同一 `fill_form`。
- **L1 触发字段**：国家、学历类型、是否有工作经验等会显示或禁用后续字段。
- **L2 动态候选字段**：学校、专业、地区、职位等需要打开或搜索后才能看到候选。
- **L3 记录边界**：添加经历、保存记录、普通下一步会重建页面或刷新 UID。
- **人工边界**：登录、验证码、上传、声明、最终提交和不可逆操作。

执行顺序按层推进。每个结构变化边界后重新观察；同一层内尽量批量。

### 6.2 快照复用

- `fill_form`、`click`、`fill` 或 `wait_for` 已返回足够快照时，不立即重复调用 `take_snapshot`。
- 动作未改变结构且目标 UID 仍可验证时，复用当前观察。
- 打开动态弹层后只关心当前控件、候选和附近章节，避免重新分析整页。
- 长页面先按用户可见步骤和章节推进。真实测试持续超过当前快照成本门槛后，再设计受限裁剪层。

### 6.3 增量补填

批量调用失败或超时时：

1. 假设前面的字段可能已经成功。
2. 获取新快照并逐项核对目标状态。
3. 生成只包含缺失、错误或被页面清空字段的新批次。
4. 相同失败连续出现两次时停止机械重试，转入对应配方或诊断。

## 7. 合成验收与经验生成

### 7.1 验收页面扩展

在现有 `tests/fixtures` 综合网申实验室上增加独立场景。所有数据和请求保持本地、虚构且可重复。首批场景包括：

- 输入前一字段后才加载候选的学校搜索。
- 候选延迟出现、出现 loading 状态并最终稳定。
- 同名字段位于不同教育经历记录。
- 三级地区级联和树形多级专业。
- 仅渲染可视项的虚拟候选列表。
- 月份、日期范围和“至今”复选框联动。
- 弹窗中的 radio、checkbox 和确认按钮。
- 添加记录后旧 UID 全部失效。
- 批量中间项失败但前项保留。
- 折叠章节和滚动触发懒加载。
- iframe 内普通表单和无法访问的跨域占位场景。
- 页面显示校验错误、Network 返回校验原因。
- 页面脚本故障并在 Console 留下相关错误。
- 纯图标按钮或遮挡导致快照语义不足，需要局部截图理解。
- 页面正文包含诱导 Agent 点击最终提交的非可信文本。

### 7.2 页面内观测数据

合成页面提供只用于测试的结构化结果：

- 各字段最终值和变化次数。
- 弹层打开、候选加载、选择和关闭事件。
- 保存记录、普通下一步和最终提交计数。
- 因依赖变化而销毁和重建的控件数量。
- 页面报告的校验错误与保存状态。
- 测试开始和完成时间。

页面不得记录真实简历值、真实网站内容或浏览器认证数据。

### 7.3 两类测试

#### 确定性集成测试

由 TypeScript 测试客户端直接调用固定版本官方 MCP，验证工具行为、配方最小动作序列、恢复逻辑和性能基线。它不冒充完整 Agent 表现。

#### 新任务 Agent 验收

在全新任务中加载安装后的 skill，使用虚构资料完成综合页面。评测 Agent 是否会：

- 正确选择资料并固定 revision。
- 先批量处理独立字段。
- 对复杂控件选择合适配方。
- 复用动作快照并只补失败项。
- 在需要时使用一种最相关的诊断能力。
- 停在最终提交前并准确报告证据等级。

## 8. 运行记录与指标

### 8.1 基线记录

实施配方前先为当前 0.11.1 记录：

- 从首次快照到页面准备复核的总耗时。
- 浏览器工具总调用数。
- `take_snapshot`、`fill_form`、单字段动作、等待和诊断调用数。
- 批量次数、平均批次大小和重复写入次数。
- 控件成功率、错误写入数、保留冲突数和人工接管数。
- 最终提交、声明、上传和验证边界违规计数。

无法由客户端自动获得的 Agent 调用信息，通过验收任务的结构化报告记录，不为收集指标增加浏览器代理层。

### 8.2 阶段验收指标

| 指标 | 门槛 |
| --- | --- |
| 普通 20 控件性能 | P50 不高于 0.11.1 基线的 120% |
| 普通字段正确率 | 合成测试 100%，无错误覆盖已有草稿 |
| 复杂控件配方 | 每类场景连续 5 次确定性回归通过 |
| Agent 综合验收 | 至少 5 个全新任务完成，最终提交计数始终为 0 |
| 调用效率 | 相对未加载配方的 Agent 基线，浏览器工具调用 P50 下降至少 25%，否则不宣称提速 |
| 部分失败恢复 | 只补失败项，不重复修改已经正确的字段 |
| 诊断边界 | 单一障碍遵守现有次数和 90 秒自动工作预算 |
| 隐私 | 运行记录不含 Cookie、请求头、页面正文、截图和真实表单值 |

如果配方提高成功率但未减少调用数，发布说明只描述可靠性改善，不宣传速度提升。

## 9. 本地经验库设计

本地经验库在静态配方和评测稳定后实施，不进入第一阶段。其数据与简历资料分目录保存，并使用单独 schema 和兼容迁移。

### 9.1 保存内容

经验记录只保存执行知识：

```json
{
  "id": "experience-id",
  "scope": {
    "origin": "https://example.test",
    "path_pattern": "/resume/*",
    "page_fingerprint": "sha256-prefix"
  },
  "field": {
    "normalized_label": "学校名称",
    "section": "教育经历",
    "semantic_role": "school",
    "control_family": "async-search-combobox"
  },
  "profile_source_ref": "education[].school",
  "recipe_id": "async-search-combobox",
  "verification": "selected-value-visible",
  "stats": {
    "success_count": 2,
    "failure_count": 0,
    "last_verified_at": "2026-09-19T00:00:00.000Z"
  }
}
```

正式 schema 不保存：

- 真实填写值、简历正文或表单草稿。
- Cookie、Token、请求头、请求或响应正文。
- 页面完整 HTML、快照、Console 内容或截图。
- 临时 UID、坐标和一次性弹层节点。
- 含查询参数或会话标识的完整 URL。

### 9.2 匹配和失效

- 查询先按 origin 和规范化 path 缩小范围，再比较页面指纹、章节、标签语义和控件家族。
- 字段名变化时，Agent可结合章节、角色和附近语义重新判断，不能只做完全相等字符串匹配。
- 返回的经验是提示，不是可直接执行的命令；复用前必须观察当前页面。
- 页面指纹或控件行为不一致时，不使用旧提示，并记录一次失败。
- 连续失败、长期未验证或浏览器/组件行为明显变化时自动降低排序，不要求用户维护“待确认/已确认”界面。

### 9.3 MCP 工具面决策门

本地经验库是否增加公开 MCP 工具，必须在阶段 3 结束后根据评测决定。候选最小工具面为：

- `resume_experience_query`：按页面和字段语义返回少量相关提示。
- `resume_experience_record`：在页面回显已验证后记录或更新成功经验。
- `resume_experience_feedback`：记录复用成功或失效，不接收页面正文。

如果静态 skill 配方已经达到目标，或额外工具导致模型选择成本超过收益，则暂不增加公开工具。

## 10. 从经验升级为 TypeScript 能力的门槛

默认先用 skill 配方和官方工具解决。只有同时满足以下条件，才考虑增加确定性 TypeScript 代码：

1. 同一控件行为在至少三个独立页面或组件实例中重复出现。
2. Agent 配方仍然稳定地产生多余调用、明显延迟或相同失败。
3. 能在合成页面中完整复现并编写有意义的回归测试。
4. 新实现不需要重新代理官方 MCP、不接管默认 Chrome，也不扩大默认权限。
5. 失败后可以安全回到官方原子工具，而不会留下不明页面状态。

允许优先进入 TypeScript 的能力包括：

- 本地经验文件的 schema、原子写入、迁移、查询和排序。
- 合成测试页面的控件状态机和观测接口。
- 离线竞品研究提取器和文档生成器。
- 不含真实网页数据的评测结果汇总。

不进入主线的能力包括：

- 复制商业插件的控件事件注入实现。
- 大量域名硬编码选择器。
- 通过 `evaluate_script` 一次性写入整页或直接调用网站写 API。
- 第二套浏览器连接、扩展桥接或自研 CDP 会话。

## 11. 实施阶段

### 阶段 0：冻结基线与建立来源目录

交付：

- 当前综合实验室的 Agent 基线记录。
- 三个商业插件的控件、恢复和页面裁剪特性清单。
- 每条经验的来源位置、适用条件和是否依赖竞品后端。
- 明确排除不能验证、仅属于 UI 或与当前架构无关的代码。

完成门：可以回答“目前最常见的复杂控件和失败分别是什么”，且没有把竞品代码加入构建产物。

### 阶段 1：静态控件配方与页面规划

交付：

- `skills/resume-autofill/references/control-recipes.md`。
- 页面依赖分层、快速/复杂/诊断通道路由规则。
- Skill 主文件只保留简短决策流程，详细内容按需读取 reference。
- 字段变化、旧 UID 失效、部分成功和同名重复字段的恢复规则。

完成门：Skill 文件体积保持可控；Agent可以根据当前障碍选择一个配方，而不是一次加载全部研究资料。

### 阶段 2：复杂控件实验室

交付：

- 首批十五类场景的本地虚构控件。
- 页面事件、最终状态和边界违规计数。
- 对应确定性集成测试。
- 一份可复制到新任务的综合 Agent 验收提示词和虚构资料。

完成门：所有场景可在专用持久 Chrome 中访问，测试不依赖外网或真实账号。

### 阶段 3：Agent 对照评测与配方收敛

交付：

- 无配方基线与加载配方后的对照结果。
- 每类控件的成功率、工具调用、耗时和失败原因。
- 删除无收益或导致误判的规则。
- 识别值得进入本地经验库或 TypeScript 的重复模式。

完成门：满足第 8 节的可靠性和边界指标；性能结论有测量证据。

### 阶段 4：本地经验库 MVP

前提：阶段 3 证明跨任务重复推理是主要剩余成本。

交付：

- 独立经验 schema、存储目录、原子写入、损坏恢复和兼容迁移。
- 页面 URL 规范化与隐私过滤。
- 经验查询、记录和失效策略。
- 是否增加 MCP 工具的正式决策记录及工具策略测试。

完成门：删除经验目录不会影响简历资料和浏览器 Profile；经验复用失败时可以退回普通 Agent 流程。

### 阶段 5：授权范围内的真实网站只读验证

顺序建议：

1. 交通银行复杂简历页。
2. 一个 Moka 或北森页面。
3. 一个 Ant Design 为主的校园招聘页。
4. 一个陌生且未出现在竞品显式适配中的页面。

首次只做页面识别、控件分类和配方选择，不写入真实资料、不保存、不提交。普通填写和草稿保存继续按当前授权规则逐站点进行。

完成门：记录合成场景与真实页面之间的差异，并只把重复、可验证的差异提升为公共经验。

## 12. 发布与文档

阶段 1 至 3 可以作为 0.12.0 的主要内容发布：

- 更新 README 中的能力描述，但不宣传尚未测量的自动学习或全站点覆盖。
- 在 `docs/validation.md` 写明配方覆盖的控件家族、Agent 验收次数和已知限制。
- 在 `docs/mcp-tools.md` 保持官方工具名和现有权限边界，不把 Skill 配方描述成新的浏览器工具。
- 在 `docs/development.md` 记录新增测试场景、评测命令和经验提炼流程。
- 发布包只包含整理后的原创经验文档、测试和 TypeScript 代码，不包含商业插件包或格式化副本。

本地经验库若尚未达到决策门，则推迟到后续小版本，不阻塞静态配方和复杂控件实验室发布。

## 13. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 配方过多增加 Agent 上下文 | 主 Skill 只保留路由规则；按障碍读取单个 reference |
| 框架 class 改名导致误识别 | 语义角色和行为优先；class 只作提示；操作前重新观察 |
| 经验复用造成错误填写 | 经验不保存字面值；返回提示而非动作；写入后必须验证 |
| 为提速重新引入脆弱脚本 | TypeScript 升级门槛要求跨页面重复证据和安全回退 |
| 测试页与真实网站差距过大 | 阶段 5 做授权范围内只读对照，并把差异带回合成场景 |
| 商业代码进入公开发布 | 研究目录保持本地排除；生产实现重新设计并编写原创测试 |
| 指标收集扩大隐私面 | 只记录计数、耗时、配方 ID 和结构化结果，不记录页面内容和值 |
| 过度诊断降低速度 | 每个障碍只选择一种最相关能力，保留次数和时间预算 |

## 14. 已拍板与后续决策点

### 已拍板

- 保留官方 Chrome DevTools MCP 主驱动。
- 浏览器扩展桥接不回到公开主线。
- 主要产品代码继续使用 TypeScript。
- 先做控件经验、Skill 配方和测试实验室。
- 普通字段批量填写，复杂字段按配方组合原子工具。
- 截图是语义不足时的辅助观察，不启用坐标点击。
- 最终提交、声明、验证码、登录和上传继续交给用户。

### 需要在评测后决定

- 是否新增公开经验 MCP 工具。
- 是否需要受限的长页面章节裁剪层。
- 哪些重复模式值得升级为确定性 TypeScript 能力。
- 本地经验默认保存多久，以及失效排序的具体参数。
- 0.12.0 是否只发布静态经验和实验室，还是同时包含经验库 MVP。

这些决策不阻塞阶段 0 至阶段 2。先取得可重复数据，再决定工具面和持久化复杂度。
