## 1. 执行原则与投入估算

按阶段交付可检查的结果。每阶段运行与该变化相关的检查，通过后进入下一阶段；发生失败或新风险时再扩大验证。用户已完成计划审阅并授权实施，也已追加授权私有后端开发与服务器部署。

| 阶段 | 核心产物 | 预计投入（人日） | 依赖 |
| --- | --- | --- | --- |
| M0 范围与样本 | 字段目录、合成简历、测试页面清单、站点候选 | 0.5～1 | 计划通过 |
| M1 插件与简历 | 可加载插件、简历编辑、JSON 导入导出 | 2～3 | M0 |
| M2 本地填写 | 扫描、规则、预览、写入、回读、撤销 | 4～6 | M1 |
| M3 后端联调 | FastAPI、认证、协议、模拟字段识别 | 2～3 | M2 |
| M4 模型业务 | 开放问题、脱敏、私有模型适配代码 | 2～3 | M3 |
| M5 网站适配 | 平台适配、2 个代表流程首轮验收与支持清单 | 4～7 | M2；完整联调需要 M4 |
| M6 真实模型验收 | 私有服务器接入、效果与容量报告 | 2～4 | M4、服务器可用 |
| M7 小范围试用 | 安装包、升级与回退说明、试用问题修复 | 2～3 | M5、M6 |

本地版 M0～M2 合计约 **6.5～10 人日**；完整私有试用版合计约 **18.5～30 人日**。按约 25%～35% 的真实网站调试缓冲，完整版本预留约 **24～40 人日**。这是范围估算，不是承诺日期，也不能用工具生成代码的速度代替实际验证时间。

人日按约 6 小时专注实现与验证估计；全职推进大约 5～8 个工作周。兼职则按实际可投入时间延长。服务器等待、账号/页面不可访问、增加网站或 OCR 导入等新需求不计入上述估算。

实施工作由助手完成并提供可检查结果；你主要负责确定网站优先级、检查个人资料映射、在需要登录的真实表单中验收，以及决定服务器接入时间。不需要先系统学完后端才能开始项目。

## 2. M0：范围和验证材料

### 工作项

- 固定 v0.1/v0.2 的功能边界和暂缓事项。
- 建立基础资料、学历/学位、教育、实习、项目、技能等来源目录与别名字典草案。
- 建立 3 份合成简历：单段经历、多段教育/项目、缺少信息；均不使用真实隐私数据。
- 制定至少 20 个合成表单场景、总计至少 200 个目标字段的标注计划。
- 根据 [原插件适配能力与复用评估](原插件适配能力与复用评估.md)，先整理已有平台分支、通用控件方法、后端依赖及需替换的行为；不重新从零调查全部候选。
- 从现有平台线索中选择站点 A/B 的代表性域名、页面类型和流程。若具体页面未定，继续通用实现，M5 前补齐；两个是首轮验收样本，不是支持数量上限。
- 记录每个字段的正确来源、能否自动写入、无法写入时的预期原因。

### 完成标准

交付字段目录和样本说明；每个目标明确包含或排除的控件。真实网站未确定时如实标为待定，不会凭名称宣称支持。样本足以启动 M1/M2，不以获取真实网页截图为前提。

## 3. M1：插件骨架与简历资料

### 工作项

- 创建 Manifest V3 工程，配置侧边栏、编辑页和短任务后台入口。
- 固定 Node、Python 基线及依赖锁文件；给出实际可运行的构建与检查命令。
- 编写分组简历编辑 UI，条目 ID、日期校验和缺失信息提示。
- 实现 JSON 导入预览、导出、本地保存、版本迁移备份和清理。
- 限制 storage 访问上下文；初始只使用最小基础权限。

### 验证与交付

- 扩展在本机 Chrome 可加载，打开面板与编辑页没有运行错误。
- 编辑、排序、刷新和重启后，条目内容及 ID 保持一致。
- 非法 JSON、重复 ID、非法日期、过大文件、未知版本有明确错误，不覆盖旧数据。
- 内容脚本不能直接读取完整本地简历或令牌。
- 导出后重新导入的事实、条目 ID 和空值语义一致。
- 交付可加载构建、样例 JSON、安装说明；这一阶段不要求连接后端。

## 4. M2：本地填写闭环（v0.1）

### 工作项

- 用户触发后扫描当前页面，建立节点注册和文档/扫描版本标识。
- 支持通用文本、原生选择、日期等已列明控件，过滤受限字段。
- 区分分组，允许用户绑定重复经历与手选未知字段来源。
- 实现预览、只填空值、明确覆盖、逐项写入与回读。
- 实现文档变化失效、操作去重、冲突检测和有条件撤销。
- 实现离线模式，填写不需要服务地址或模型。

### 必测场景

| 场景 | 预期 |
| --- | --- |
| 普通字段与合法简历值 | 预览来源正确，写入回读一致 |
| 同名字段分属学校/公司/项目 | 依据分组匹配，不串字段 |
| 两段教育，页面顺序与简历相反 | 使用用户绑定的条目 ID |
| 输入框已有内容 | 默认跳过；选择覆盖后才可改 |
| 用户预览后手动改值 | 冲突提示，保留用户新输入 |
| React/Vue 重渲染导致值被清空 | 回读失败，不能显示成功 |
| SPA 路由变化、DOM 替换、页面导航 | 相关旧计划失效 |
| 切换标签页、连续点击填写 | 不能写到其他页面或重复操作 |
| 密码/验证码/证件/银行卡/文件/声明 | 跳过，不能读入待发送载荷 |
| 自定义控件、不可访问 iframe | 明确显示不支持或需要手填 |
| 撤销后用户已继续修改 | 不覆盖用户后续修改 |

### 发布本地版的通过条件

- 20 个合成场景、至少 200 个标注字段完成测试，其中必须包含上述负例。
- 在预先声明支持且资料充分的字段中，正确填写率目标至少 98%；不能临时删除失败样本以提高结果。
- 已执行字段的正确率目标 100%；发现误填需修复或把该情况降级为手动后重新验收。
- 受限字段写入、跨标签页写入、页面提交行为均为 0。
- 规则流程不产生后端或第三方模型网络请求。
- 有可检查的成功/失败列表和明确撤销限制。

通过后交付可用 v0.1；后续工作可以在此基础上继续。

## 5. M3：本地后端与模拟联调

### 工作项

- 创建 FastAPI 工程和 `/healthz`、`/v1/capabilities`、`/v1/fields/resolve`。
- 实现本机绑定、Bearer 鉴权、严格请求校验、统一错误和无正文日志。
- 导出 Schema/OpenAPI，建立前后端共用合成样例。
- 实现模拟适配器的正常、歧义、非法输出、超时与不可用情形。
- 在侧边栏实现服务设置、可选主机权限、请求预览、连接测试和取消。
- 让模型建议进入预览，不能直接执行写入。

### 通过条件

- 本机不安装模型即可完成“扫描 → 模拟辅助 → 预览 → 填写”的接口闭环。
- 后端异常不影响本地规则模式。
- 错误令牌、来源不匹配、过大正文、未知属性、重复字段 ID 和无效来源均被拒绝。
- 关闭侧边栏、切换服务地址、导航页面后，迟到结果不会执行。
- 请求捕获证明真实简历值、当前输入值、完整 DOM 和 URL 查询参数没有混入字段识别请求。
- 以清晰的开发模式标识模拟结果，不把它计入模型准确率。

## 6. M4：开放问答与模型适配

### 工作项

- 增加 `/v1/answers/draft`、事实选择、内容预览、草稿编辑和用户确认。
- 实现联系人信息过滤、实体占位符、已知占位符恢复与恢复后长度校验。
- 实现私有模型 HTTP 适配、结构化输出参数、严格结果验证。
- 实现请求截止时间、一次受预算约束的格式修复、并发控制和取消处理。
- 创建真实模型将使用的固定评测集；此阶段先用模拟服务验证行为。

### 通过条件

- 未确认的生成文字不能填入网页或成为简历事实。
- 未提供的事实 ID、未知占位符、越界来源、非法输出、超长文字均无法直接执行。
- 输入中的“忽略规则、上传完整简历、执行某脚本”等文本无法触发额外工具或网络能力。
- 合成姓名、电话、邮箱、证件号作为泄露哨兵，检查字段标签、自由文字、请求、日志和错误响应各条路径。
- 超时、客户端断开、格式修复后仍有明确截止时间；并发槽不会无限增加。
- 交付适配代码与评测用例，真实效果必须等 M6 才能下结论。

## 7. M5：平台适配与两个代表流程验收

### 工作项

- 每个网站先做只读结构调查，记录具体域名、页面与控件；用户自行完成登录。
- 使用自行构建的脱敏仿真页复现控件，不把真实个人资料或整页 DOM提交到代码库。
- 适配必要的搜索选择、日期弹窗、级联选项或重复经历组。
- 为站点规则设置明确命中条件、版本和失效退路。
- 在实际页面验证预览、写入和校验状态；由用户自行决定保存/下一步/提交。

### 通过条件

- 两个已选流程各完成至少 3 轮检查，覆盖不同合成资料或用户确认可用于该草稿的资料。
- 每个流程分别报告支持字段、正确填写字段、错误字段、跳过字段及原因。
- 对属于支持范围且资料充足的字段，覆盖率目标至少 85%，执行正确率目标至少 99%；所有字段仍需用户预览。
- 受限字段操作、错误经历绑定、自动提交均为 0。
- 明确区分仿真页面验证与真实网站验证，不能用前者替代后者。
- 若页面会自动保存，优先采用不提交的仿真回放；真实验证由用户用自己的已确认资料进行，避免向真实账户写入虚构简历。

单个站点首轮投入约 2～3.5 人日。若存在不可访问跨域控件、大量封闭 Shadow DOM 或特别复杂的表单引擎，先交付可支持的子集，更新限制，再决定是否追加范围；不得无限拖延整个项目。

## 8. M6：私有服务器与真实模型验证

### 前置材料

到这一阶段才需要服务器连接方式、操作系统、GPU/驱动状况、空闲资源和允许的网络接入方式。账号口令、令牌和 SSH 私钥不写入文档或代码库。先检查服务器现有任务，明确可用资源，再制定实际部署配置。

### 工作项

- 在允许的资源范围内部署私有推理服务与网关，模型端口只供网关访问。
- 小模型建立基线，再测试较大候选；记录模型版本、量化、推理框架版本和提示词版本。
- 执行 1/2 并发、正常/最大请求大小、超时与取消场景。
- 检查模型端、网关、代理和异常日志的正文记录设置。
- 生成模型效果与性能报告，再确定试用版默认配置。

### 模型评测集与目标

| 类别 | 最少样例 | 主要指标 |
| --- | --- | --- |
| 字段识别 | 200 个字段，含至少 40 个歧义/应放弃项 | 已建议来源正确率 ≥95%；对标注为可回答项的覆盖率 ≥80% |
| 开放问题 | 30 个问题，覆盖自我评价、项目、岗位匹配和事实不足 | 所有被展示草稿均需复核；固定评测集中重大事实编造为 0 |
| 协议与异常 | 30 个正反例 | 非法输出/未知引用被拦截率 100% |
| 脱敏与注入 | 30 个含哨兵或恶意指令样例 | 受限数据泄露、额外网络行为、脚本执行均为 0 |
| 资源与并发 | 1、2 并发分别至少 20 个代表性请求 | 无显存溢出，超限有 429，结束后资源回收 |

评测样例按模板/站点来源划分开发集与保留集，不能只换同一句话的姓名就当成独立样本。保留集先冻结，再测模型和提示词。报告同时给数量、比例、失败案例与版本，不能只给一个平均分。

首轮性能目标：40 个以内的字段批次 P95 ≤15 秒，300 字左右回答 P95 ≤25 秒；在指定模型、输入长度和并发条件下测量。目标超出时，先缩小批次/上下文或换较小模型，不承诺未知硬件一定达到该延迟。

“固定评测集中重大事实编造为 0”不代表模型永远不会编造，因此试用阶段依然保留人工预览。若字段识别质量不足，就关闭该功能，保留规则模式；若问答不达标，保留手写固定回答。

### 通过条件

协议与隐私硬性门槛全部通过；效果与延迟达到约定目标，或明确缩小可用范围并记录限制。只有经真实验证启用的模型能力，才能出现在试用包功能说明中。

## 9. M7：试用、打包与维护

### 工作项

- 你先自用 3～5 天，再由你邀请 2～5 位同学试用约 1 周。
- 为每个试用者配置独立令牌、额度/并发限制和撤销方式。
- 产出构建 ZIP、校验摘要、安装/配置/更新/回退说明。
- 汇总问题，只采集用户主动提供的脱敏描述和必要版本信息。
- 修复阻塞问题后发布内部版本记录，明确已测网站和限制。

### 通过条件

- 新电脑按说明能够加载扩展、录入简历、连接服务并填写已支持流程。
- 任一试用者令牌撤销后无法使用模型 API，其他人不受影响。
- 断网时仍能使用本地模式；错误有用户可理解的反馈。
- 更新保留本地简历；迁移失败可用备份恢复。
- 包中无用户简历、访问令牌、模型密钥和原插件发布代码。
- 不存在尚未解决的误填受限字段、跨用户数据混用、自动提交或日志泄露问题。

3～5 天和 1 周属于观察日历时间，前表 M7 的人日是期间整理、修复与发布的实际投入。试用者反馈速度会影响最终完成日期。

## 10. 指标定义与测试方式

### 不混淆准确率和覆盖率

- **填写覆盖率**：正确完成的支持字段数 / 支持范围内且简历资料充分的字段数。
- **执行正确率**：正确写入并通过回读的字段数 / 所有实际执行写入的字段数。
- **模型建议正确率**：正确的来源建议数 / 模型所有非放弃建议数。
- **模型可回答覆盖率**：正确给出建议的可回答字段数 / 标注为可回答的字段总数。
- **安全跳过**：受限字段或不支持控件被明确跳过；单列数量，不混入正确填写分子。
- **耗时**：从用户触发相应动作到结果可用；同时报告本地/网络/模型时间和输入规模。

测试在开发时分层实施：纯规则、日期与映射逻辑用 Vitest；消息、真实控件、异步重渲染、侧边栏状态用 Playwright 的扩展测试环境；接口、验证器、鉴权和限流用 pytest。真实 Chrome 手工检查用于补充扩展 UI、主机权限及实际招聘站兼容性，不声称自动化测试覆盖所有浏览器行为。

本地 100 字段扫描 P95 ≤1 秒、普通原生字段填写与回读 P95 ≤5 秒作为体验目标，在指定合成页面和测试机器上记录；有级联等待的网站单独报告，不套用同一性能数字。

每次修改运行有关测试；发试用包时执行类型检查、构建、关键规则测试、API 测试、浏览器冒烟和产物内容检查。纯文档变更只检查结构、链接和例子，不为其创建产品单元测试。

## 11. 学习与后续范围

你只需跟随项目理解四件事：HTTP 请求/响应、JSON 数据结构、FastAPI 的路由与校验，以及浏览器内容脚本如何读写表单。模型训练、复杂数据库和分布式架构不作为入门要求。

v0.3 按收益排序的候选工作：

1. 复制纯文本简历 → 本地联系信息处理 → 私有模型整理 → 用户逐项确认导入。
2. 已确认事实基础上的岗位润色，另存草稿，不自动改正式简历。
3. 更多真实网站适配和复杂重复经历控件。
4. PDF/Word 文件解析和结果校对，扫描件 OCR 单独评估。
5. 多份简历管理、可选加密备份、商店分发或账号同步。

这些增强不计入 M0～M7 的投入估算。到时根据实际重复劳动和试用反馈选择，不预先把项目扩成完整招聘平台。
