# 公共申请表适配记录

更新：2026-09-11。插件 0.3.2；后端继续使用 0.3.0。本文记录实际公开页面的只读调查和自行编写的仿真回归，尚不构成登录后真实填写验收。

## Lever

样本：[TXI 的公开申请入口](https://jobs.lever.co/txidigital/7c014a14-dce6-431c-9920-0dc1e9759c81/apply)。使用全新匿名浏览器配置检查，没有登录、输入资料、上传或提交申请，也没有访问用户当前的 Chrome 页面。

发现并修复：

- `Full name✱`、`Email✱`、`Phone ✱` 的实心必填星号此前未参与标准化，导致规则没有命中；现在能匹配本地姓名、邮箱和电话来源。
- 自定义问题的标题位于独立 `.application-label`，并未用标准 `label` 关联控件。现在优先读取同一题的唯一标题，避免把 `cards[…]` 或通用占位提示当成问题名称。
- 同一题的错误提示和位置搜索状态不会混入标题。位置字段需要选择搜索结果，当前明确交给用户手选。
- 声明题标题参与受限字段判断；单选组的各个选项仍使用自己的标签，声明不会作为普通回答自动写入。

规则版本为 `leverAdapterVersion = 1`。命中条件同时要求：`jobs.lever.co`、组织名/UUID/`apply` 路径、`form#application-form`、同一 `.application-question` 的 `.application-field` 和唯一 `.application-label`。结构缺失或歧义时回退通用扫描；相似域名和其他路径不启用此规则。

修复后公开页只读扫描共取得 14 个字段：3 个基本字段取得明确来源，1 个位置控件提示手选，10 个字段保留人工来源选择或手填。没有执行真实网页写入，不能把这三个字段的识别结果称为整页填写覆盖率。

## Greenhouse

另行检查了 [Artefact 的公开申请入口](https://job-boards.greenhouse.io/artefact/jobs/7797496002)。首次观察到姓名拆分、邮箱/电话、搜索式下拉和教育年月拆分控件；后续两次浏览器复查超时。目前没有发布 Greenhouse 专用适配，也没有推断姓名拆分或自动补全日期。

通用扫描新增读取 `aria-required="true"`，作为原生 `required` 的补充；必填属性变化会使旧填写计划失效。

## 验证与证据

新增 1 项规则测试、4 项表单浏览器回归和 1 项真实浏览器升级/回退测试。浏览器回归使用独立编写的 HTML，所有网络请求被拦截并替换为本地仿真页；没有向招聘网站写入测试资料。

- 姓名、邮箱、电话和已维护的固定回答：读取标题、预览、填写、回读、撤销。
- 位置搜索、声明题：不自动写入；提交计数为 0。
- 用户在预览后改值、网站改标题：保留用户内容，使旧计划失效。
- 域名、路径、表单 ID 或唯一标题不匹配：不启用专用规则。
- ARIA 必填变化：预览包含必填状态，变化后拒绝旧计划。

机器证据：`artifacts/public-application-baseline.json`、`artifacts/public-application-inspection-*.json`、`artifacts/browser-regression-0.3.2.json`、`artifacts/browser-upgrade-0.3.2.json`。独立调查脚本为 `scripts/inspect-public-application-forms.mjs`；仿真页为 `tests/fixtures/lever-application.html`。

当前合计 35 项 TypeScript 单元测试和 37 项浏览器回归通过。网页与插件同步另有 4 项整链路回归。原先国聘/智联等登录后页面仍需用户确认访问范围，两个代表性真实流程各三轮的完整验收保持未完成。

升级验证使用发布的 0.3.1 安装包，在私有临时浏览器目录保存合成资料和合成连接配置，关闭浏览器后替换为 0.3.2 并重启，再替换回 0.3.1 并再次重启。三个阶段的扩展 ID 相同，资料、修订号和连接配置保留。测试未使用用户当前 Chrome 配置，临时目录已清理。
