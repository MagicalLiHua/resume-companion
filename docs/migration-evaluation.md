# 0.11 迁移决策验证

日期：2026-09-18。环境：macOS、Apple Silicon、Node.js 24.15.0、Google Chrome 153.0.8010.52、`chrome-devtools-mcp` 1.9.0。所有测试均使用本地虚构页面和虚构资料。

## 结论

继续采用“资料 MCP + 官方 Chrome DevTools MCP”的 0.11 路线。主要收益是减少 Agent 工具轮次、获得 Network/Console/截图/定点脚本等疑难诊断能力，并删除长期维护的扩展、Native Host 和自研页面协议。这个决定**不是**因为官方 MCP 的浏览器端逐控件执行比旧扩展更快；同机微基准表明旧扩展的批量 DOM 执行更快。

新路线的普通 20 字段 P50 为 4.429 秒，达到计划中热运行低于 15 秒的门槛。用户体感是否改善仍取决于 Agent 是否坚持一次快照、一次批量填写并复用附带快照；如果把一个批次拆成许多模型工具回合，任何底座都会变慢。

## 同机数据

### 12 个原生复选框

| 路线 | 调用方式 | P50 | P95 |
| --- | --- | ---: | ---: |
| 0.10 扩展基线 | 12 次逐字段动作 | 1.081 s | 1.250 s |
| 0.10 扩展优化 | 1 次 `set_values` | 0.988 s | 1.000 s |
| 0.11 官方 MCP | 1 次 `fill_form(includeSnapshot=true)` | 2.816 s | 2.854 s |

这些数据只统计浏览器工具执行与本地测试调用，不含模型思考、审批等待和真人操作。旧路线的逐字段组在同一个 Playwright 测试进程中循环调用，不等于真实 AI 的 12 个完整模型往返，因此不能拿 1.081 秒代表旧产品的端到端体验。官方 MCP 的 `fill_form` 内部仍按数组顺序处理并等待每个元素，这解释了它的较高浏览器端延迟。

### 20 个普通控件

官方 MCP 对 12 个文本输入、4 个原生下拉和 4 个复选框连续运行 5 次：

- P50：4.429 s
- P95：4.461 s
- 最大附带快照响应：3,430 bytes
- 页面回读正确，最终提交计数为 0

### 长页面快照

220 个已有值字段和说明文本的单次完整快照：

- 响应：43,695 bytes
- 粗略估算：10,924 tokens
- 未截断，最后一个字段可见

官方快照没有旧协议的 scope 分页。当前先依赖按页面分步、避免无意义的重复快照和复用工具附带快照；如果真实网站持续出现更大的单页，再评估受限的裁剪层。

## 功能与失败恢复

已验证：

- 文本、多行文本、原生下拉、复选框和月份控件。
- 通过通用 UID、点击、等待和批量填写完成三级异步学校级联，保存后记录回显正确。
- 批量后项 UID 无效时，前项保留；重新快照后可以只补缺失项。
- `wait_for` 自带的新快照可直接复用。
- Network 能定位合成 Fetch 请求；请求详情中的合成 Authorization 值被脱敏，响应正文未写文件。
- Console、UID 局部截图和带 `waitForStableDom:false` 的定点只读脚本可按需使用。
- 页面、响应和 Console 中的诱导文本只作为数据；测试没有执行其“点击最终提交”内容。
- 关闭 MCP 后浏览器随上游退出；重新启动复用同一 Profile，站点状态保留。用户检查页面时应保持当前任务打开。

## 权限与生命周期

`.mcp.json` 的默认浏览器工具策略为 `prompt`。普通观察与填写工具有显式自动批准；脚本、请求详情、导航、按键、对话框和拖拽保持提示；上传和 Lighthouse 禁用。自动测试会核对该矩阵，但客户端的真实审批 UI 仍需在安装后的新任务中观察。

启动器在 MCP 进程启动时获取 Profile 锁。第二个任务不会静默切换 Profile，资料 MCP 仍可使用。上游通过 pipe 启动的 Chrome 在 MCP 关闭时退出；持久 Profile 保存登录和站点状态，下一次页面调用可重新打开。

## 决策约束

0.11 是有人监督的开发预览版。工具名审批不能判断一个具体 `click` 是否为最终提交，因此本版本不宣称代码级绝对防误投递。若未来需要无人监督运行，需要增加参数级安全网关或进一步缩小自动动作面。
