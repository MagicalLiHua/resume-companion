# 网页端简历维护、邀请码与 API Key

> **历史产品方案**：下一版采用[纯插件版产品研发计划](纯插件版产品研发计划.md)，不依赖账号、网页后台或模型 API。下文保留当时的设计，不作为下一版需求。

更新：2026-09-10，依据用户在后端开发期间补充的下一阶段方向。本文件保留制定时的方案。2026-09-11 已完成并部署网页维护版，当前交付状态见 [网页维护版进度与验收](网页维护版进度与验收.md)。

## 用户流程

1. 管理员在网页管理区生成邀请码，设置使用次数和有效期。
2. 用户凭邀请码注册账号，登录自己的简历工作台。
3. 上传 PDF，等待解析；逐项检查基本信息、教育、经历、项目、技能等内容，确认后保存为正式简历。
4. 用户在网页编辑个人信息及简历，创建、命名和切换不同简历版本，指定默认填写版本。
5. 用户创建个人 API Key，只在创建时显示完整值，将它填入插件设置。
6. 插件从我们的业务后端读取该用户已确认的简历版本，在网申页面扫描、预览、填写、回读与撤销。

API Key 是本系统给插件使用的凭证。模型推理服务的内部凭证由后端持有，插件只连接业务后端。

## 参考来源与取舍

已只读查看 [求职方舟简历页面](https://www.qiuzhifangzhou.com/resume)：未登录页面可见上传入口、版本切换、职位及更新时间、编辑简历 MD、下载和删除入口。其 [官方填写手册](https://www.qiuzhifangzhou.com/doc/manual/autofill.html) 描述了上传解析、检查修正、管理多个版本及插件选择版本的流程。此次没有注册其账号、上传文件、编辑或删除其数据；登录后实际保存行为尚未验证。

| 参考能力 | 我们的实现范围 |
| --- | --- |
| 上传并解析简历 | 首先支持 PDF，产出待确认的结构化草稿 |
| 在线编辑 | 使用现有简历字段结构，编辑基础资料、多段教育、经历、项目、技能、证书和固定回答 |
| 多个简历版本 | 命名、复制、更新、默认版本、预览、删除；插件手动选定版本 |
| 插件使用网页简历 | 同步用户确认的版本，显示版本名与最后同步时间 |
| 下载 | 保留 JSON 导出；排版后 PDF 导出单列为维护增强，不是 PDF 解析的前置条件 |
| 账号与接入管理 | 采用用户指定的邀请码注册与个人 API Key 机制 |

第一版围绕用户指定的简历维护和自动填写。找岗位、招聘表格、面试辅导、岗位润色与简历内容包装不进入这次新增范围。

## 页面划分

普通用户：注册/登录、我的简历、PDF 导入与结果确认、简历编辑与预览、API Key 管理、账号设置。

管理员：邀请码列表与生成、用户状态管理、用量及服务状态。普通用户只能管理自己的简历和密钥；管理员日常页面以账号、额度和运行状态为主，不默认展示用户简历正文。

当前服务器没有外网，首版账号注册采用邀请码加用户名/密码，不依赖邮件或短信发送。管理员引导与账号恢复流程在开发时一起实现，不能把公开默认密码写入安装包。

## 后端需要新增的内容

当前后端已有字段辅助、草稿、令牌摘要认证和模型适配。网页端需要增加真正的账号与资料服务，不能仅给现有命令行管理套一个页面。

| 模块 | 数据与接口职责 |
| --- | --- |
| 用户与会话 | 用户名、密码哈希、状态、角色；注册、登录、退出、会话失效 |
| 邀请码 | 摘要、有效期、次数、使用记录；注册时以事务核销，避免并发超额注册 |
| API Key | 用户归属、名称、可识别前缀、摘要、权限、有效期、最近使用和撤销状态 |
| 简历 | 用户归属、版本名、结构化资料、修订号、默认版本；读取、编辑、复制、删除 |
| PDF 导入任务 | 上传文件归属、解析状态、提取文本、待确认草稿、错误原因及清理期限 |
| 使用记录 | 每用户/密钥的持久化额度与必要元数据，代替当前重启会重置的内存计数 |

数据保存在关系型数据库，原始 PDF 放在项目私有文件目录。所有资料读写根据认证用户过滤；猜中另一个用户的简历 ID 也不能读取。网页编辑携带修订号，遇到旧版本写入返回冲突，避免两个页面互相覆盖。

网页采用可撤销的登录会话；插件使用权限受限的 API Key。默认插件权限为读取已确认简历及调用必要的字段辅助，资料编辑通过网页进行。密钥撤销后后续请求立即失效，账号禁用时所有密钥同时失效。API Key 管理和邀请码管理需要独立的身份/权限检查。

PDF 解析流程：校验文件类型、大小和页数 → 在受限任务中提取文字 → 私有模型转换为现有结构 → 标出不确定项 → 用户确认保存。不得把模型猜测直接写进正式资料。先完成可提取文字的 PDF；扫描件需要 OCR，必须明确提示并单独准备离线 OCR 依赖，不能将空文本解析显示为成功。

首次从本地插件迁移时，由用户在差异预览中确认上传现有资料；不静默上传所有浏览器存储。服务端保存是用户新增需求，替代早期“只在浏览器保存”的产品范围，当前已部署基础服务本身尚未保存简历。

## 插件联调

插件设置服务地址、API Key 和默认简历版本，支持连接检查、同步、清除凭证及同步失败反馈。凭证只保存在可信扩展存储中，不提供给网页内容脚本；内容脚本只取得本次预览后允许填写的字段值。

继续使用现有字段来源目录、经历绑定、只填空值、预览失效和撤销逻辑。网页更新简历后插件刷新同步；每次填写绑定明确的简历修订号。离线时保留用户已同步且仍在本机的版本，并显示同步时间。退出或切换账号时清除上一账号的缓存和密钥。

## 模型与 vLLM

业务层继续调用统一的 `ModelAdapter`，对插件保持稳定的 `/v1/fields/resolve` 等业务协议。当前实际适配和运行的是 Ollama；后续增加 vLLM 的 OpenAI 兼容适配器，将服务地址、模型名、结构化输出参数、就绪检查和内部凭证限制在服务端配置。

[vLLM 官方文档](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/) 提供 OpenAI 兼容服务接口；这使业务适配可行，但不代表直接把当前 Ollama 地址替换成 vLLM 地址就能运行。现有 GGUF 权重是否适合候选 vLLM 版本、模型架构、量化与双卡配置，需要另行实测。换推理框架主要改变部署和吞吐，语义效果仍取决于模型及提示词。

模型镜像、权重、Python 依赖和前端静态资源全部在有网电脑准备，再传入离线服务器。PDF 解析与字段辅助可以配置不同的模型任务，但先复用现有服务验证接口，暂不占用另一张 GPU 部署未经测试的候选模型。

## 开发顺序与验收

1. 实现数据库迁移、用户/会话、邀请码和 API Key，并验证两个账号间的数据隔离与密钥撤销。
2. 实现简历版本增删改查和网页编辑，复用现有数据校验，验证修改冲突与备份恢复。
3. 实现 PDF 上传、解析任务、待确认草稿和错误提示，覆盖文字 PDF、空白/加密/损坏/超限文件及扫描件提示。
4. 接入插件 API Key 与简历同步，完成“注册 → 上传 PDF → 确认资料 → 创建密钥 → 插件填写”的完整验收。
5. 再做代表性招聘网站适配，并按同一套冻结样例比较候选模型或 vLLM 部署。

前四项完成后才称为网页维护版。当前基础后端交付和合成模型评测，不能替代账号、上传或真实网站的验收。
