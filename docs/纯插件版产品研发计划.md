文档版本：1.4 交付版  
更新日期：2026-09-11  
适用范围：下一版纯浏览器插件；建议插件版本号为 0.4.0  
状态：本次本地开发与安装包已完成，包含多版本简历、补充资料、模型辅助、自动悬浮窗口和独立投递记录。69 项单元测试、51 项浏览器测试及真实 DeepSeek 链路通过；真实网站按用户安排后续试用。

## 1. 审阅摘要

### 1.1 已确认的产品方向

用户安装一个浏览器插件，在插件自带的完整资料管理页面中维护简历。需要从 PDF 整理资料时，复制插件提供的提示词，在自己常用的 AI 中上传简历，再将 AI 输出的固定模板 Markdown 粘贴回来。插件在本地解析、展示可编辑字段，经用户确认后保存，供招聘网页填写使用。

| 决策 | 确定方向 |
| --- | --- |
| 产品形态 | 纯浏览器插件，包含完整标签页和填写侧边栏 |
| 数据位置 | 当前浏览器配置中的插件本地存储，支持备份和迁移 |
| AI 使用方式 | 简历整理仍由用户自行使用外部 AI；P0 同时提供可选的模型 API 字段匹配，由插件直接请求用户配置的提供商 |
| 导入格式 | 用户输入 Markdown，程序转换为内部结构化 JSON |
| 日常修改 | 可以修改 Markdown 草稿，也可以直接修改资料表单 |
| 补充资料 | 简历之外的必要信息在插件内单独维护资料表，本地保存并纳入完整备份 |
| 字段匹配 | 首版采用稳定字段定义、明确别名、分组约束；陌生名称和歧义字段可由模型辅助，最终由用户核对 |
| 自动填写 | 已确认资料、本地规则、用户预览和确认；申请由用户自己提交 |
| 基础设施 | 不依赖业务后端、本地服务、桌面客户端或注册；本地功能无需 Key，模型辅助使用用户自己的 API Key |
| 界面 | 延续黑白色系、中文为主、清晰显示未保存状态 |

下面是建议默认值，供审阅调整，不重新讨论已确认的纯插件方向。

| 编号 | 本文建议 | 对首版的影响 |
| --- | --- | --- |
| R1 | 多份命名简历已纳入首版，可新建、复制、切换、重命名和删除 | 编辑版本与本次填写版本分别选择，完整备份保存全部版本 |
| R2 | 投递记录与统计纳入本次交付，自动留下页面信息 | 独立记录页；无待确认/已确认流程，直接记录、编辑和统计 |

首版验收重点是：Markdown 能准确进入可编辑资料，保存和备份可靠，已支持字段能在预览后正确填写。网站覆盖数量是单独的长期工作，不能用导入成功代替网站兼容验收。

### 1.3 本轮补充决定（2026-09-11）

用户确认增加本地补充资料表，维护简历未提供但网申需要的信息；重新导入简历时保留手工补充资料。随后明确将模糊字段的模型辅助匹配升为 P0，首轮用 DeepSeek Anthropic 格式测试，并支持配置其他兼容提供商。首版同时建设本地规则与模型匹配器，记住各网站对应关系继续后置。

详细数据、交互与接口见[补充资料与字段匹配设计](补充资料与字段匹配设计.md)和[纯插件模型 API 与模糊字段匹配](纯插件模型API与模糊字段匹配.md)。本机 Key 已用于独立测试扩展的合成字段直连验证；正式插件通过设置页配置 Key，不能直接读取电脑环境变量。用户已授权完整开发，随后将多版本简历和自动悬浮入口纳入本次，并明确先完成安装包，真实网站稍后试用。

## 2. 产品定位与用户需求

产品面向需要反复填写网申资料、愿意自行使用 AI 整理简历的个人用户。一次整理真实经历，在不同申请页面重复使用；用户始终能看见数据来源、修改内容和决定最终提交。

| 用户问题 | 产品提供的结果 |
| --- | --- |
| PDF 中的经历需要反复手工整理 | 一份可复制的提示词和固定 Markdown 模板 |
| AI 整理后有错漏 | 导入预览、问题定位和普通表单编辑 |
| 不懂 JSON 或程序配置 | 日常只操作 Markdown、表单与按钮 |
| 关闭浏览器后希望继续使用 | 持久保存正式资料与编辑草稿 |
| 担心重新导入覆盖自己的修改 | 显示字段差异，确认后进入编辑区，再保存正式版本 |
| 不同招聘网站重复录入 | 本地匹配、手动绑定经历、预览与有限填写 |
| 简历没有写全网申需要的资料 | 本地补充资料表，保存后可选择为填写来源 |
| 不同公司给同一字段起不同名称 | 明确别名与分组匹配，陌生表达可用模型辅助，仍可手动选择来源 |
| 换电脑需要带走资料 | 导出完整备份，另一台电脑导入 |
| 希望知道投过哪些公司 | 后续提供用户手动确认的投递记录 |

产品目标是减少重复输入。首版不提供代投、求职结果保证、自动生成经历或全网站兼容承诺。

## 5. 页面结构与交互

### 5.1 插件自带的完整标签页

入口暂定为“我的简历”，由侧边栏的“编辑资料”打开。页面属于插件安装包，离线可加载，不是服务器网页。

| 页面/区域 | 内容与主要操作 |
| --- | --- |
| 我的资料 | 基本信息、教育、工作与实习、项目、技能、证书、固定回答；保存资料 |
| 补充资料 | 维护额外资料名称、内容与含义说明；保存后纳入填写来源，提供新增、编辑、删除 |
| 模型设置 | 接口格式、HTTPS 地址、模型名、用户 Key、在本机记住、连接测试与清除配置 |
| 从 AI 导入 | 使用步骤、复制提示词、Markdown 输入、解析、问题列表与差异预览 |
| 备份与设置 | 完整备份导入导出、当前资料 Markdown 导出、上一份恢复、清除资料、版本与使用说明 |
| 独立投递记录页（P0） | 公司、岗位、网址、记录时间、筛选、编辑、导出及统计 |

无数据时显示“从 AI 导入”和“手动填写”两个明确入口。示例资料必须通过用户点击载入，不能默认为真实资料。

黑白界面保持统一。保存状态采用文字提示，不能只靠颜色；长段经历、错误信息、按钮焦点和键盘操作应可用。主要目标是桌面浏览器，不为手机扩展设计独立产品。

### 5.2 悬浮窗口与侧边栏


招聘页面右下角自动出现悬浮球，点击后在右下角展开窗口。用户选择本次使用的简历版本，窗口自动扫描；核对来源、经历和可填内容后，点击带确认图标的按钮开始填写。资料页中未保存的其他版本草稿不参与本次操作。工具栏侧边栏保留为替代入口。

悬浮球与网站样式隔离，内部使用可信扩展页面；每次嵌入关联本页的随机会话令牌，网页自行伪造的 iframe 不能读取简历或 Key。相关设计与参考插件观察见[多版本与悬浮填写](多版本与悬浮填写.md)。

保留“扫描当前页”“检查来源和经历”“填写选中项”“查看结果/撤销”。显示当前正式简历和修订状态；来源选择包含已保存的补充资料，展示匹配依据并允许处理歧义。编辑区尚未保存的草稿不参与填写。

对未匹配或歧义字段提供“用模型辅助匹配”，显示目标提供商与待发送内容；用户确认后从可信侧边栏直连 API，返回后标记模型建议，仍需用户核对。模型调用不因普通扫描自动发生。

不设置登录、云端同步或模型连接前置步骤。未保存任何正式简历时引导用户进入资料页。

### 5.3 第一次使用

1. 用户安装插件，打开“我的简历”。
2. 点击“复制解析提示词”，在自己常用 AI 中粘贴，并上传自己的 PDF 或提供简历文字。
3. 将返回的 Markdown 粘贴到插件，或直接手写/修改模板。
4. 点击“解析并预览”，检查字段、经历数量、日期及无法识别内容。
5. 处理阻塞问题，确认差异后载入编辑区；可继续修改普通表单。
6. 点击“保存资料”，插件提示已保存到当前浏览器。
7. 用户进入招聘网页，点击插件，扫描、预览并确认填写。

外部 AI 输出不满足模板时，插件给出具体位置与修改办法，允许复制“修正格式说明”回到原对话；不自动向任何 AI 发送文本。

### 5.4 后续修改

常规小改动直接在表单中完成。简历以外的必要信息在“补充资料”中维护，首版提供可选空白常用条目及自定义文本项；已有手机、邮箱等使用原字段，避免同一事实重复维护。需要用 Markdown 修改简历时，可选择“编辑按当前资料生成的 Markdown”，或查看并编辑上次导入原文。

原始导入文档标明对应的导入时间和修订，不把它显示成已经同步了后续表单修改。重新解析后必须再次查看差异。修改输入文本、基础简历或经历顺序后，旧解析预览失效。

### 5.5 草稿与冲突

Markdown 输入和资料表单均提供本地草稿恢复，默认停输约 1 秒保存草稿，显示“草稿已保存”；点击“保存资料”才更新正式简历。关闭页面前未落盘的修改仍有离开提示。

同一份活动草稿可同时保留 Markdown 输入缓冲和表单编辑缓冲，后者包含补充资料；切换页面不能清空其中任意一份。“应用到编辑区”会替换表单草稿中的简历部分，保留当前补充资料；已有未保存修改时先明确展示将替换的内容。仅查看历史原文不执行替换。

草稿记录其基于的正式修订号，并有独立的草稿修订与编辑实例标识。同一份活动草稿只能由一个编辑实例自动保存，另一窗口需显式接管，不能用自动保存覆盖它。另一标签页保存了正式更新时，本页保留草稿并提示冲突。用户可以先导出草稿，再载入最新资料；恢复旧草稿也需要核对差异。

## 6. Markdown 导入方案

完整模板、可复制提示词、容错规则和映射表见[Markdown 简历模板与解析规范](Markdown简历模板与解析规范.md)。此附件是开发和测试的共同依据。

采用固定的章节标题、中文字段标签、普通列表和重复经历小节。用户输入 Markdown，内部保留结构化 JSON；不要求用户填写内部 ID 或修订号。

解析器只做确定性的格式处理：读取明确字段、标准化日期表达、映射已定义枚举。不得推测姓名、补造工作经历、把“硕士”推断为已获硕士学位，或把“未提供”当成“否”。

| 结果级别 | 例子 | 产品行为 |
| --- | --- | --- |
| 可直接识别 | 姓名、邮箱、标准年月、明确的工作经历列表 | 显示字段及来源，等待核对 |
| 需核对但可保留 | 未支持章节、只有年份的时间、非标准枚举 | 显示原文和定位，用户明确决定是否暂不用于填写 |
| 阻塞应用 | 同一字段出现不同值、无效日期、结束早于开始、状态矛盾 | 保留草稿；修正或明确清空问题字段后再应用 |

解析成功不代表事实正确。用户核对姓名、学校、日期、经历归属等内容后，才成为正式资料。

重新导入以“替换简历章节，保留补充资料表”为首版规则，不做简历章节之间的模糊自动合并。删除的简历字段和经历必须在差异中显示。只有姓名等少数字段的新文档，也不能在未提示的情况下清掉原来的全部经历。解析器不拥有手工补充资料；应用层保留当前草稿中的补充字段，并在预览中明示范围。

## 7. 数据设计与保存策略

### 7.1 多版本与正式资料

填写只使用本次选择的简历版本的正式快照。版本库维护每份资料及其上一份，编辑页另有当前编辑版本；悬浮窗口或侧边栏可以选择不同的填写版本，不改变正在编辑的草稿。Markdown 原文、未保存草稿和解析问题不能作为填写数据。

| 数据 | 内容 | 用途 |
| --- | --- | --- |
| versions / activeVersionId | 最多 30 份命名简历，每份正式快照与上一份，以及当前编辑版本 ID | 按版本 ID 读取正式资料；切换填写版本不切换编辑草稿 |
| current / previous | 当前编辑版本的正式快照与上一份 | 与版本库在同一存储提交中同步 |
| fieldMetadata | 以稳定条目 ID 和字段名关联的日期原文、精度及核对状态 | 保留只有年份或具体日期的信息；随字段编辑更新，用于回看和 Markdown 导出 |
| sourceDocument | 原始 Markdown、模板版本、导入时间、对应修订、未识别片段 | 回看和重新导入，不假装与后续表单编辑自动同步 |
| draft | 编辑模式、Markdown/表单缓冲、基础修订号、草稿修订、编辑实例、草稿 ID 和时间 | 意外关闭后恢复，不参与填写 |
| previousSnapshot | 上一份完整的正式资料、字段元数据及其导入来源 | 用户确认后恢复 |
| applicationJournal（P0） | 页面提交动作捕获或用户手动登记的公司、岗位、网址与进展 | 独立记录修订，与完整备份一同保存；普通填写不生成投递记录 |
| preferences | 本地界面偏好、引导状态 | 普通非凭证设置 |
| modelSettings | 当前协议、HTTPS 地址、模型名称、配置修订 | 可进入完整备份；恢复后须重新授权和配置 Key |
| modelCredential | 与模型目标和协议关联的用户 Key | 独立的可信 session/local 存储；不进入资料备份、草稿或上一份 |

存储容器建议升级为 `storageSchemaVersion: 2`；简历结构建议演进为 `schema_version: 1.1`，用于明确表达未知状态。两者用途不同，迁移与导入校验分别处理。

Profile 1.1 同时增加 `supplemental_fields`，每项包含稳定 ID、语义标识、显示名称、说明、文本类型和值；旧版迁移时初始化为空数组。补充资料与简历共用正式保存、草稿、修订和上一份机制，其修改同样使填写预览失效。明文原始 Markdown 的“补充信息”保留栏目不直接转为这些正式字段。

现有教育状态含布尔字段，初始值不能表达“未知”。新结构将 `completed`、`is_current`、`is_expected_end` 等状态允许为 `null`，`experience[].kind` 也扩为 `work / internship / null`；`null` 表示未提供。与之相关的编辑、来源目录、备份和填写逻辑同步适配。旧版明确保存的值保持原样迁移，不替用户重新解释事实。

### 7.2 本地持久化

使用 `chrome.storage.local` 保存主要状态，后台统一串行提交，并按预期修订号检查冲突。正式资料、字段元数据、对应原文与上一份备份组成一个版本化存储对象，一次提交；不能先清空当前内容再尝试保存。

开发时限制只有可信扩展页面可直接访问资料存储。内容脚本仅收到本次已选字段所需的值，不通过网页消息开放资料读取。浏览器重启后重新读取正式状态，不能依赖后台进程常驻。

Chrome 的本地扩展存储可跨浏览器重启保留，卸载扩展会清除；常规容量为 10 MB。首版设置总数据预算和写入失败处理，不先申请无限存储权限。[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)

建议限制：Markdown 输入 256 KiB、正式资料 1 MiB、最多保留一份完整上一版和一份活动草稿；总数据达到 8 MiB 时提示导出与整理。限制按 UTF-8 字节计算，超限保留现有正式数据，不截断内容。完整备份上限也为 8 MiB。投递记录上限 1000 条、单条备注 2000 字符，同时服从总容量限制。

### 7.3 备份、恢复和 Markdown 导出

- 默认完整备份为带版本号的 JSON 文件，包括正式简历及补充资料、字段元数据、导入原文、草稿、上一份、本地偏好、非凭证模型设置和后续投递记录；备份不含模型 Key 或历史服务器凭证。模型设置恢复后默认未启用，重新配置 Key 和授权后才能使用。
- “导出当前简历 Markdown”由当前正式资料生成固定模板，供人阅读和继续交给 AI。另有“导出导入原文”，名称区分用途。
- Markdown 导出不能被称为完整备份：它不包含所有本地状态；原文中未映射的内容需作为“补充信息”章节导出。手工补充资料表默认不额外附入简历 Markdown，界面写明范围，并通过完整 JSON 备份迁移。
- 旧版结构化简历 JSON 可导入，按更新简历、保留当前补充资料处理；完整新备份先校验版本、大小和内容，展示包括补充资料在内的恢复范围，再由用户确认。
- 恢复作为一个新修订提交；恢复前当前正式资料保留为上一份，拒绝在冲突时强行覆盖。备份文件中的“正式版”和“上一份”可分别预览并选择恢复，默认选择正式版；不把文件中的历史递归追加到本地上一份中。其他内容按展示并确认的恢复范围处理，原备份文件保持完整。
- 未知的未来版本不尝试猜测迁移。导入失败保留原文件和现有数据，提供可理解的错误说明。

本地保存不等于加密保险箱；首版不承诺抵御掌握电脑账户或浏览器配置文件的人。产品不接收 PDF 原件、不采集网站密码或验证码。模型 Key 由用户在可信设置页主动输入，默认仅存会话，可选择在本机记住；从资料导出结构上排除独立凭证。用户粘贴的原文会留在本地，不能宣称程序已自动识别和删除其中的全部敏感文字。

简历整理采用用户主动复制文字或导入文件；P0 模型辅助则由可信扩展侧边栏直连用户选定的 API。匹配器采用异步可替换接口，输入字段与资料来源描述，输出来源候选及依据；实际值在本地解析，用户预览后由既有链路填写。模型提供器不持有网页操作权，关闭侧边栏或页面/资料/配置变动时取消并丢弃过期结果。类型、过滤和失败处理见两份专项设计。沿用现有技术栈，不新增桌面运行时、业务服务或通用 Agent 框架。

解析器输出 `candidate + issues + sourceMap + templateVersion + unmapped`，候选中包含需保留的日期精度元数据。解析阶段不持久写入，也不生成网页写入指令；条目 ID 在候选形成时一次性分配并在该次预览期间保持稳定，不因重新渲染变化。

内部操作边界为：读取状态、保存草稿、预览导入、保存正式资料、恢复备份、扫描网页、执行已确认填写。每项使用明确消息类型，不提供任意路径读写或通用执行接口。

## 9. 自动填写范围与网站兼容

首版先使用已验证站点规则、标准字段定义与明确别名，结合分组和控件语义确定来源；多段经历仍须绑定具体条目。公司换用未定义名称时，可请求模型给出候选，再由用户核对简历或补充资料来源；同名异义不自动混用。跨次记忆网站对应关系后置。

| 场景 | 首版处理 |
| --- | --- |
| 普通文本框、邮箱、电话、textarea | 字段来源明确且用户确认后填写 |
| 补充资料文本、不同名称的同义字段 | 使用已保存来源及明确别名；有歧义时手动选择 |
| 原生 select、radio | 选项唯一对应时填写；歧义保留给用户 |
| 年月字段 | 使用已确认年月；需要完整日期而只有年月时提示手填 |
| 明确的技能复选项 | 支持已确认技能；不处理协议或声明类勾选 |
| 多段教育、工作、项目 | 用户将网页分组绑定到稳定的经历 ID |
| 网页已有值 | 默认保留；覆盖须在预览中明确选择 |
| 预览后页面或资料变化 | 原预览失效，重新扫描/核对 |
| 自定义下拉、地区级联、iframe、Shadow DOM | 未经专用验证的场景提示手填 |
| 密码、验证码、证件号、银行卡、文件上传、协议、提交 | 用户自己处理 |

首轮真实验收选择两个结构有区别、用户实际需要且可进入的流程。国聘、智联、前程/应届生是既有候选，Lever 有局部公开页证据；根据可访问性选取，不要求此刻先确定所有网站。

每个支持条目记录域名、页面类型、插件版本、日期、已验证字段、跳过项和限制。填写动作可能触发网站自动保存，真实试验前确认具体页面与允许操作范围；虚构简历只用于本地仿真页。插件不自行提交申请。

## 10. 投递记录与统计（P0）

独立的插件标签页 `journal.html`，从侧边栏或资料页进入。记录公司、岗位、投递网址、记录时间、备注和跟进状态，支持搜索、筛选、编辑、删除、CSV / JSON 导出及完整备份恢复。

按用户最新决定，不区分“待确认”和“已确认”，新记录直接进入列表和统计。默认状态为“已记录”，可自行改为面试中、已获 Offer、未通过、已撤回。统计展示记录岗位数、已识别公司数、面试中与 Offer 数；这些是本地记录统计，不宣称验证了招聘网站的真实投递成功。

用户打开插件并扫描页面后，内容脚本观察本页的原生提交事件，并在随后有限时间内观察新增的成功提示。捕获时带入当前网址和页面中可识别的岗位/公司信息，同一扫描会话不重复记账。招聘网站没有对应事件或发生跨页面跳转时可能无法自动捕获，可点“记录这次投递”或在记录页手动添加。

公司和岗位优先读取网页已有的 JobPosting 结构化信息，岗位标题可从页面主标题带入。无法识别的部分直接留空，用户按需编辑；网址过滤明显的登录令牌和追踪参数，保留岗位链接。普通扫描和点击插件“填写”本身不产生投递记录，插件也不自动提交。

记录上限 1000 条、备注上限 2000 字符；与资料共用本地容量预算，写入失败不删除旧记录。记录无需模型 API、业务后端或账号。

## 11. 旧版本迁移与范围收敛

### 11.1 用户资料迁移

保持当前扩展身份和数据迁移路径，不通过卸载来升级。检测旧的 `resume_profile`、`resume_backup` 和修订信息，在新容器中生成并校验迁移结果；成功写入并读回后才标记迁移完成。任何失败都保留旧数据并提示导出。

旧插件中已同步到本地的正式资料可以继续使用。仅在历史网页中的资料，需要用户先从网页导出简历 JSON，再导入新插件；不会自动扫描或拉取旧服务器。

迁移后的正式资料与旧备份应可恢复。新版 1.1 的完整数据不能假定可直接由旧插件读取；回退使用升级前导出的 1.0 备份，保留新版本完整备份供再次升级。

### 11.2 连接功能与权限处理

在新纯插件发布包中移除历史网页账号同步、业务服务器地址、插件连接 Key 和旧服务状态等入口与请求代码；新增独立的模型提供商设置与用户模型 Key 管理。旧服务器连接凭证不导出、不迁入新正式状态；确认本地资料迁移成功后，清理旧连接记录及不再需要的授权，不能调用会连同资料一起清除的旧“断开连接”流程。

按用户批准的自动悬浮入口，扩展保留 `activeTab`、`scripting`、`storage`、`sidePanel`，声明普通 HTTP/HTTPS 网页主机权限及顶层内容脚本。自动入口由页面和域名线索决定是否显示，可在设置中关闭；不注入浏览器内部页或默认扫描子框架。模型请求仍由可信页面发往用户配置的 HTTPS 目标，应用层约束地址与路径。[activeTab 官方说明](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[扩展跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

### 11.3 仓库与历史服务

服务端、网页和相关验收文档作为历史成果保留，但不进入纯插件运行依赖。实现阶段检查并清理刚开始的桌面开发依赖、未完成的桌面配置和后端记录实验，防止误算完成状态；需要保留的记录需求重新在插件中实现。

本计划不会删除线上数据、停止服务器或撤销用户已有服务凭证。若以后确定下线历史服务，先完成数据导出和另行安排；新插件不能以旧服务是否关闭作为启动条件。

## 12. 开发阶段与排期

以下原始估算基于现有代码复用、固定模板和一份当前简历；是有效开发工作量，不是承诺的交付日期。本轮增加补充资料表、本地匹配器、实际模型直连与设置、发送预览和故障处理，相关阶段工作量需重新估算。真实网站访问和人工试用的等待时间另计。每阶段以可演示结果和验收证据结束。

## 13. 验收与质量目标

以下均为计划门槛，不是当前版本的测试结果。

| 维度 | 门槛 |
| --- | --- |
| 标准模板 | 固定样本的全部已提供字段与预期值一致，缺失信息不生成事实 |
| 容错输入 | 支持范围内的格式变化正常识别；范围外内容明确定位并保留 |
| 数据可靠性 | 关闭/重启、保存失败、冲突、升级、恢复场景不静默覆盖或丢失正式资料 |
| 正式数据边界 | 草稿、未确认候选和未知字段不参与自动填写 |
| 补充资料 | 保存、重启与备份可恢复；重新导入简历不清空手工表，补充资料修改使旧填写预览失效 |
| 字段匹配接口 | 异名同义可匹配、同名异义不混填；可替换提供器仍须通过来源校验、修订检查和预览确认 |
| 纯插件 | 断开所有后端服务后仍可导入、编辑、保存、导出及填写本地仿真表单 |
| 网络边界 | 仅用户主动的模型连接测试和匹配请求可访问已授权提供商；不请求历史业务服务、远程脚本或遥测，未启用模型时无模型请求 |
| 模型辅助 | DeepSeek Anthropic 真实扩展测试通过，两种协议适配通过；候选需严格校验及用户确认，故障后本地功能可用 |
| 凭证与数据 | 模型 Key 不进入包、备份、日志或内容脚本；默认只外发用户确认的最少字段描述，资料值本地解析 |
| 写入正确性 | 固定合成用例中的已选支持字段准确写入；误填、越组、未确认覆盖、自动提交为 0 |
| 真实网站 | 每个声明支持的流程有版本和页面证据；发现误填即阻塞该适配器发布 |
| 性能 | 参考电脑上 50 KiB 典型文档解析与校验目标 P95 ≤ 500 ms；256 KiB 上限输入不持续冻结页面，超过约 1 秒显示进度并可取消 |
| 使用体验 | 首次用户拿到符合模板的 AI 输出后，目标 5 分钟内完成导入核对并保存；通过实际观察验证 |

沿用 TypeScript 类型检查、Vitest 领域测试、Playwright 真实扩展测试及已有关联回归。只有网站变化或新失败证据需要时才扩展适配测试，不把重复跑同一套测试当作新增覆盖。

## 14. 发布、安装与维护

首个交付包为纯插件 ZIP、SHA-256 校验、安装/升级说明、模板与提示词、版本说明和已测兼容清单。包中只包含运行所需扩展资源，不含真实简历、账号数据、服务器 Key、Python/Electron 依赖或测试凭证。

内测时由用户解压，在 Chrome / Edge 开发者模式加载扩展。保持稳定的加载目录和扩展身份，升级前提供导出提示。Chrome 官方开发流程支持加载已解压扩展。[安装方式](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world)

面向更广泛用户时再准备商店发布材料：产品介绍、权限说明、隐私说明、截图、支持范围和反馈入口。商店审核时间不计入研发完成时间，未上架前不展示虚假的商店安装按钮。

自用观察建议 3–5 天，再由产品负责人自行发给少量同学试用。反馈采用版本、站点、页面类型和脱敏复现步骤；不自动上传原始简历或整页 DOM。每次更新同时检查模板版本、备份兼容和网页适配版本。

## 15. 主要风险与应对

| 风险 | 处理方式 |
| --- | --- |
| AI 改写模板或夹带解释 | 固定提示词、有限容错、行号提示、保留未识别内容 |
| AI 编造或误解经历 | 提示词限制、来源展示、人工核对；结构校验不宣称能判断事实真伪 |
| 表单和 Markdown 修改冲突 | 单一正式 JSON、原文标记、基于修订号的差异应用 |
| 缺失状态被误当作否/已毕业 | 显式未知状态，缺失项不自动填写 |
| 升级或旧连接清理误删资料 | 先迁移并读回验证，再清理凭证；保留升级前备份 |
| 原文、草稿和历史占满存储 | 输入和总量预算，保留一份上一版；写入失败不清空当前资料 |
| 网页字段或控件变化 | 结构指纹、执行前校验、回读、失效后停止；不宣称所有网站可用 |
| 卸载或换浏览器丢失本地数据 | 可见的完整备份与迁移入口，不承诺自动跨设备同步 |
| 首版被附加功能拖延 | P0/P1 独立验收，客户端、内置模型和 PDF/OCR 不回流到首版 |
