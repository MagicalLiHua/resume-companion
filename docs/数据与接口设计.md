# 数据与接口设计

> **历史服务端方案**：下一版改为纯插件。新的本地存储和迁移设计见[纯插件版产品研发计划](纯插件版产品研发计划.md)，Markdown 契约见[模板与解析规范](Markdown简历模板与解析规范.md)。以下 HTTP 接口记录用于维护已有版本，不是新版依赖。

版本：0.2 实现补充 · 2026-09-10。以下保留目标协议及合成示例。后端已实现，实际接口以 `contracts/api/openapi.json`、`backend/app/schemas.py` 和语义校验为准；部署与限制见 [后端说明](../backend/README.md)。本地数据校验以 `extension/src/domain/profile.ts` 为准，页面消息以 `extension/src/domain/types.ts` 为准。插件的 AI 交互尚待接入。

实现补充：增加认证后的 `/v1/readiness`、`/v1/source-catalog` 和 `/v1/openapi.json`。来源目录中的 `path/label/group/value_type` 必须与服务端规范一致，项目分组的 API 值为 `project`，对应本地 `projects`。`contracts/api/requests.ts` 负责显式构造最小请求、验证引用并恢复已知占位符；字段的当前值、完整简历和网页 URL 不属于请求 DTO。

模型预热期间返回 `503 MODEL_WARMING_UP`；超出文本或保守上下文预算返回 413，不静默截断事实。草稿中的新数字或部分头衔会标记 `UNVERIFIED_NUMBER` / `UNVERIFIED_CLAIM`，所有草稿仍需用户复核。具体错误和限制以生成的 OpenAPI 为准。

用户最新要求增加网页账号、邀请码、个人 API Key 和服务端简历存储，详见 [网页端与账号体系方案](网页端与账号体系方案.md)。这些新增 API 尚待设计和实现；现有字段辅助请求仍不接收真实简历值，未来资料 CRUD 与 PDF 上传会使用单独的认证接口。

## 1. 数据分层与版本

必须区分四种数据对象：

| 对象 | 保存位置 | 内容 |
| --- | --- | --- |
| `ResumeProfile` | 可信扩展本地存储 | 用户确认的真实简历 |
| `LocalFormSnapshot` | 当前会话内存 | 页面节点引用、当前值、分组绑定、字段描述 |
| `ResolveRequest` / `DraftRequest` | 一次请求与服务端内存 | 明确允许发送的最小数据，不是前两者的直接序列化 |
| `FillPlan` | 当前会话内存 | 经预览确认、绑定当前文档的具体写入值 |

简历使用 `schema_version: "1.0"`；API 使用 `/v1` 和 `protocol_version: "1.0"`。两者分别演进。API 主版本不兼容时，客户端保留本地功能并停止模型请求，提示更新，不尝试猜测字段。

线上的未知字段默认拒绝；新可选字段通过版本协商引入。允许的来源路径是受控目录项，不用 JavaScript `eval`、任意 JSONPath 或可执行模板解析。

## 2. 本地简历结构

以下示例完全为合成数据，不来自你的真实简历。`null` 表示未知或未填写；不能因为网页要求必填就补造内容。

```json
{

  "profile_id": "profile-demo",
  "revision": 1,
  "basic": {
    "full_name": "示例同学",
    "email": "student@example.com",
    "phone": null,
    "city": "南京",
    "job_intention": "测试开发工程师"
  },
  "education": [
    {
      "id": "edu-1",
      "school": "示例大学",
      "major": "计算机技术",
      "education_level": "master",
      "degree": null,
      "expected_degree": "engineering_master",
      "completed": false,
      "study_mode": "full_time",
      "start_month": "2024-09",
      "end_month": "2027-06",
      "is_current": true,
      "is_expected_end": true
    }
  ],
  "experience": [
    {
      "id": "exp-1",
      "kind": "internship",
      "organization": "示例公司",
      "role": "测试开发实习生",

        {"id": "fact-exp-1", "text": "编写并维护接口回归测试用例"}
      ]
    }
  ],
  "projects": [
    {
      "id": "project-1",

      ]
    }
  ],
  "skills": ["Python", "接口测试"],
  "certificates": [],
  "custom_answers": [
    {"id": "answer-1", "title": "自我评价", "text": "此处填写用户审核后的固定回答"}
  ]
}
```

### 2.1 校验规则

- 各条目与事实 ID 在所属简历内唯一，编辑和排序不改变 ID。
- 姓名等基础字段允许未填；具体网申缺值在预览时报告，不要求先填写所有个人资料。
- 学历与学位分开，不能把“硕士研究生”和“工学硕士”视为同一字段。
- `degree` 只表示已取得的学位；在读阶段尚未授予则留空，拟取得学位放在 `expected_degree`。`completed` 明确该教育经历是否完成。最高已完成学历按已确认状态计算，不能仅按数组位置或预计毕业时间推断。
- 年月为 `YYYY-MM`，完整日期为 `YYYY-MM-DD`。已知到月份时，不自动补成当月 1 日。
- 日期需合法，结束不早于开始。`is_current` 与预计结束时间可以同时存在，但实际结束和预计结束必须区分。
- 不用毕业年月推断出生日期、年龄、性别、政治面貌等未提供事实。
- 本阶段结构中不储存密码、验证码、证件号和银行卡号。
- 自由文字只作为文本保存和显示，不接受富 HTML、脚本或远程图片。
- JSON 导入初始上限 1 MiB；预览新增、修改与缺失内容，用户选择替换后才保存。无静默合并多份简历。
- 迁移前保留一份本地旧版本；迁移失败保持旧数据可导出，不能清空重建。

### 2.2 事实与生成文本分开

`facts` 是用户提供并确认的事实。模型生成结果先保留在本次预览，用户选择保存为固定回答后进入 `custom_answers`，不会自动追加到事实库。

若后期支持文本解析，解析结果也先作为导入草稿，按条目确认后才能成为正式简历。这样能避免模型猜测被后续回答反复当作真实经历。

### 2.3 来源目录的初始范围

| 来源 | 页面语义 | 取值规则 |
| --- | --- | --- |
| `basic.full_name/email/phone/city/job_intention` | 基本联系信息与求职意向 | 只在本地读取，对应键没有值就跳过 |
| `education[].school/major/education_level` | 某一段教育的学校、专业、就读层次 | 先绑定具体教育条目 |
| `education[].degree/expected_degree` | 已获学位/拟获学位 | 根据页面语义严格区分，不能互相补值 |
| `education[].start_month/end_month` | 就读起止年月 | 区分实际与预计，不补造日 |
| `experience[].organization/role` | 工作或实习单位与岗位 | 检查条目 `kind` 与网页分组一致 |
| `projects[].name/role/technologies` | 项目名称、角色与技术 | 先绑定具体项目；技术列表使用本地格式化 |
| `skills` | 技能列表 | 根据控件类型转成文本或匹配本地选项 |
| `custom_answers[].text` | 用户保存的固定回答 | 用户先选择回答条目，不自动取第一条 |

表中的斜线是文档缩写，实际目录展开成单独路径，如 `basic.email`。尚未确认语义的字段不进入自动目录。自定义问题、证书特殊等级、薪资或是否接受调剂等判断项由用户补充，不根据模型推测。

## 3. 本地表单快照与写入计划

`LocalFormSnapshot` 不发送到后端。建议字段如下：

| 字段 | 用途 |
| --- | --- |
| `sessionId` | 当前侧边栏操作会话 |
| `tabId`, `documentId`, `frameId` | 防止写入错误标签页或导航后的新页面 |
| `scanRevision` | 每次扫描/相关结构变化递增 |
| `profileRevision` | 简历变更后使旧预览失效 |
| `fieldId` | 本次扫描随机 ID，不暴露 CSS 路径 |
| `elementRef` | 内容脚本内节点引用，不能跨进程序列化给模型 |
| `groupId`, `entryBinding` | 网页分组与本地经历 ID 的对应 |
| `label`, `inputKind`, `constraints` | 经过本地分析的语义与控件限制 |
| `originalValue`, `optionValueMap` | 覆盖冲突、撤销及枚举写入，仅在本地保留 |

多个教育分组的例子：用户把网页“教育经历 1”绑定 `edu-2`，把“教育经历 2”绑定 `edu-1`。随后 `education[].school` 根据该绑定取值，不按照简历数组当前排序隐式决定。

`FillPlan` 必须包含上述会话版本、唯一 `operationId`、目标 `fieldId`、期望旧值、拟写入值和来源。创建预览不等于授权执行；只有本次确认的计划可以发送给内容脚本。

收到执行消息时，内容脚本校验扩展来源与当前会话令牌。网页 `postMessage`、DOM 自定义事件或页面提供的 JSON 不得触发简历读取、服务请求或写入命令。真实字段值一旦写入目标招聘页面，就会被该网站读取，这属于用户确认的填写行为。

## 4. 公共 API 约定

- `Content-Type: application/json`；除健康检查外，必须带 `Authorization: Bearer <token>`。
- 不用 Cookie 认证；令牌不放在 URL、错误消息或日志中。
- 所有响应带随机 `X-Request-ID`，POST 正文也有 `request_id` 用于客户端关联。
- `Cache-Control: no-store`，不把用户请求/草稿作为 CDN 或应用共享缓存。
- 请求体初始上限 128 KiB（按 UTF-8 字节），网关和应用都限制；压缩正文默认拒绝。
- 错误响应不回显输入值。需特别覆盖框架的参数校验错误处理，避免默认错误详情带出请求内容。
- 客户端严格限制可连接的服务 origin 和路径，禁用跨源重定向；令牌只发送给当前明确配置的服务。
- 后端结果不是写入指令；最终取值、校验和用户确认均在插件完成。

## 5. 健康检查与能力协商

### `GET /healthz`

只用于判断进程是否存活，不触发模型推理，不泄露模型地址或用户信息。

```json
{"status": "ok"}
```

### `GET /v1/capabilities`

需要鉴权。示例为开发模拟模式：

```json
{
  "protocol_version": "1.0",
  "mode": "mock",
  "features": {
    "resolve_fields": true,
    "draft_answer": true
  },
  "limits": {
    "max_body_bytes": 131072,
    "max_fields": 40,
    "max_facts": 20,
    "max_answer_characters": 1000,
    "request_deadline_seconds": 45
  }
}
```

`mode` 只允许 `mock` 或 `private_model`。模拟模式在开发测试界面明确标记，不能让使用者误认为已经接入模型。能力协商成功只代表协议与认证通过，不代表模型质量或容量已验证。

## 6. 字段辅助识别

### `POST /v1/fields/resolve`

目的：判断一个网页字段应读取哪类简历信息。姓名、邮箱等**真实值不进入请求**。常见字段已由本地规则完成，此接口处理剩余歧义。

```json
{
  "protocol_version": "1.0",
  "request_id": "req-resolve-demo-1",
  "fields": [
    {
      "field_id": "f-17",
      "label": "所获学位",
      "group": "education",
      "group_label": "教育经历",
      "input_kind": "select-one",
      "required": true,
      "option_labels": ["学士", "硕士", "博士"]
    }
  ],
  "source_catalog": [
    {
      "path": "education[].education_level",
      "label": "学历层次",
      "group": "education",
      "value_type": "enum"
    },
    {
      "path": "education[].degree",
      "label": "所获学位",
      "group": "education",
      "value_type": "enum"
    }
  ]
}
```

有效响应：

```json
{
  "protocol_version": "1.0",
  "request_id": "req-resolve-demo-1",
  "results": [
    {
      "field_id": "f-17",
      "status": "suggested",
      "source_path": "education[].degree",
      "confidence": 0.94,
      "reason_code": "LABEL_AND_GROUP_MATCH"
    }
  ]
}
```

不确定时返回：

```json
{
  "field_id": "f-17",
  "status": "abstain",
  "source_path": null,
  "confidence": 0.2,
  "reason_code": "AMBIGUOUS_FIELD"
}
```

这是单项结果示例；完整响应仍需包在 `results` 中并携带版本与请求 ID。

### 6.1 字段与取值限制

| 项 | 初始约束 |
| --- | --- |
| `fields` | 1～40 个，`field_id` 不重复 |
| `label` / `group_label` | 分别最多 120 / 80 个 Unicode 码点，先脱敏再发送 |
| `group` | `basic`, `education`, `experience`, `project`, `skills`, `other` |
| `input_kind` | `text`, `email`, `tel`, `textarea`, `select-one`, `radio`, `date`, `month`, `checkbox` |
| `option_labels` | 最多 80 项，每项最多 80 个码点；只含清理后的可见选项文本 |
| `source_catalog` | 最多 120 个受控来源项，来自插件内置目录，不含简历值 |
| `source_path` | 必须属于本次提供的目录，与分组和控件类型兼容 |
| `confidence` | 0～1，仅供显示参考；不能独立决定写入 |
| `reason_code` | 受控枚举，由插件翻译为说明，避免回显模型任意文字 |

`reason_code` 初始集合：`LABEL_AND_GROUP_MATCH`、`ALIAS_MATCH`、`AMBIGUOUS_FIELD`、`NO_COMPATIBLE_SOURCE`、`INSUFFICIENT_CONTEXT`。

### 6.2 结果处理

- 请求和结果中的字段 ID 必须一一对应；未知 ID、重复 ID 或越界来源使整批结果不可采用。
- 缺失项由服务端补成明确的 `abstain`；不能默默把它当成已处理成功。
- 本地已有高确定性匹配的字段不被模型覆盖。
- 模型建议初始不自动勾选；用户检查后才能加入填写计划。
- `education[].degree` 必须先有当前网页组与本地条目的绑定，再读取真实值。
- 枚举映射在本地进行。如“工学硕士”是否可映射为“硕士”，由明确的层级字典和页面选项判断；无法唯一决定则手选。
- 没有值时显示“简历缺少此信息”，不得要求模型编造。
- 不为自由开放问题自动选择任意大段经历，改走下一接口并由用户选事实。

## 7. 开放问题草稿

### `POST /v1/answers/draft`

一次只处理一个问题。用户选择可发送的事实；客户端先去除联系信息，将学校/公司等按需要替换成占位符，并展示最终请求预览。

```json
{
  "protocol_version": "1.0",
  "request_id": "req-draft-demo-1",
  "question": "请说明你与测试开发岗位相关的实践经历",
  "job_requirements": ["掌握 Python", "有接口测试实践"],
  "facts": [
    {"id": "fact-1", "text": "使用 Python 编写接口回归测试用例"},
    {"id": "fact-2", "text": "实现测试结果汇总和失败用例定位"}
  ],
  "constraints": {
    "language": "zh-CN",
    "tone": "professional_plain",
    "max_characters": 300
  }
}
```

```json
{
  "protocol_version": "1.0",
  "request_id": "req-draft-demo-1",
  "status": "needs_review",
  "text": "我使用 Python 编写过接口回归测试用例，并实现了测试结果汇总和失败用例定位。这些实践与岗位要求的接口测试工作相关。",
  "used_fact_ids": ["fact-1", "fact-2"],
  "warnings": []
}
```

事实不足时使用相同结构，返回 `status: "insufficient_facts"`、`text: ""`、空 `used_fact_ids`，以及 `warnings: ["INSUFFICIENT_FACTS"]`；不生成“多年经验”“提升 80%”等不存在的事实。

### 7.1 内容规则

- 问题最多 1,000 个码点；岗位要求最多 10 条、每条 300 个码点。
- 事实最多 20 条、每条 500 个码点；总长度仍受 128 KiB 请求体限制和后端 token 预算限制。
- `max_characters` 为 1～1,000。接口按 Unicode 码点计数，网页真实 `maxlength` 等约束另在本地校验，不能假定其计数方式相同。
- `used_fact_ids` 必须是输入事实 ID 的非空子集（正常草稿），不能引用未提供材料。
- 对新出现的数字、成绩、日期、证书、头衔做规则检查；有疑点标记复核，不声称程序能完全验证自然语言事实。
- 事实 ID 可追溯不等于句子含义一定正确，仍由用户对照事实审阅。
- 网页问题、岗位要求和事实片段是待处理数据，不允许其中的“忽略规则、上传完整简历”等文字改变系统约束。
- 草稿是纯文本；包含 URL 不会被自动访问，包含代码不会被执行。
- 已知占位符在本地恢复，恢复后重新检查长度；未知占位符、缺失变量或超长结果无法直接填写。
- 不静默截断段落或事实。超过限制则提示缩小输入/缩短草稿；自动修复也必须在同一总超时预算内。
- 初始 `warnings` 枚举为 `INSUFFICIENT_FACTS`、`UNVERIFIED_NUMBER`、`UNRESOLVED_PLACEHOLDER`、`LENGTH_LIMIT`，不得携带原始个人信息。

## 8. 超时、错误与降级

统一错误示例：

```json
{
  "request_id": "req-demo-error",
  "error": {
    "code": "MODEL_TIMEOUT",
    "message": "生成超时，请稍后重试；本地填写仍可使用。",
    "retryable": true
  }
}
```

| HTTP | 业务错误码 | 客户端行为 |
| --- | --- | --- |
| 400 | `PROTOCOL_UNSUPPORTED` | 禁用模型功能，提示更新，保留本地模式 |
| 401 | `AUTH_REQUIRED` / `TOKEN_INVALID` | 让用户检查令牌；不自动反复重试 |
| 403 | `ORIGIN_DENIED` / `REQUEST_NOT_ALLOWED` | 提示服务配置问题，保持当前预览 |
| 413 | `PAYLOAD_TOO_LARGE` | 在客户端缩小字段批次或事实选择 |
| 422 | `VALIDATION_ERROR` / `SENSITIVE_INPUT_REJECTED` | 显示字段名和错误类型，不回显原值 |
| 429 | `RATE_LIMITED` / `SERVER_BUSY` | 返回 `Retry-After: 5`，用户稍后重试 |
| 502 | `MODEL_OUTPUT_INVALID` | 保留手动处理，不能把原始模型结果写到网页 |
| 503 | `MODEL_UNAVAILABLE` | 继续使用本地规则，不自动切换到外部模型 |
| 504 | `MODEL_TIMEOUT` | 请求失败，当前已确认的本地字段仍可填写 |

浏览器端的 `STALE_PAGE`、`VALUE_CONFLICT`、`TARGET_NOT_FOUND`、`READBACK_MISMATCH` 是本地执行错误，不发送模型处理。

超时按单一截止时间计算：总共 45 秒，其中每次模型调用不超过 30 秒；最多一次格式修复必须使用剩余预算。客户端 60 秒截止并支持取消。浏览器不会自动重试 POST；“重试”由用户触发新请求，并产生新的请求 ID。

服务器尽力向模型取消任务，但不能承诺断开客户端后 GPU 立刻停止。并发槽应在底层调用确实结束或超时后释放，避免浏览器连续取消制造无限后台推理。

## 9. 消息与模型输出校验层次

1. **网页到内容脚本**：网页信息始终视为不可信输入；不接受页面的高权限命令。
2. **内容脚本到侧边栏**：校验扩展 ID、目标标签页/文档、消息类型、会话与长度；不接受自定义服务地址和任意脚本。
3. **侧边栏到 API**：用专门 DTO 构造函数重新生成允许字段，禁止直接序列化简历或 DOM 快照。
4. **API 到模型**：使用固定模板与输出约束；不开放工具调用、联网检索或文件访问。
5. **模型到 API**：结构、枚举、来源范围、引用 ID、长度和冲突校验。
6. **API 到侧边栏**：再次校验响应，并确认本地扫描版本和简历修订号仍有效。
7. **侧边栏到内容脚本**：只有用户确认的具体操作；执行前重新检查目标和当前值。

## 10. 协议实现与验证交付

实施时建立共享合成样例，至少包含：合法请求、未知字段、重复 ID、无效来源、不同学历/学位、多个教育条目、超长文字、模型输出注入、未知占位符、请求正文中的合成手机号/证件号。

服务端导出 JSON Schema/OpenAPI，TypeScript 与 Python 用同一组样例验证，避免“服务端接受、插件拒绝”或相反的情况。模型用的输出 Schema 可以是业务 Schema 的受支持子集，但不能绕过完整业务校验。

本文件的 JSON 只用于明确协议方向。后续若控件实测或模型兼容性要求修改协议，需同步更新本文、共享样例、类型定义和相应验收案例。
