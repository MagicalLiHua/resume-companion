# 纯插件模型 API 与模糊字段匹配

文档版本：1.0 · 2026-09-11  
状态：按用户决定将模型辅助字段匹配升级为 P0；扩展直连可行性已实测，产品界面及完整填写链路尚未实施。  
关联：[主计划](纯插件版产品研发计划.md)、[补充资料与字段匹配设计](补充资料与字段匹配设计.md)、[任务与验收](纯插件版任务与验收.md)。

## 1. 可行性结论

可以保持纯浏览器插件形态。资料、Markdown 和补充表存本地；用户配置自己的 API Key 后，由可信扩展页面直接请求所选模型服务。产品不需要业务后端、账号、桌面程序或常驻本地服务。离线时继续维护资料和使用本地规则；模型辅助匹配需要联网。

Chrome 支持扩展页面在获得目标主机权限后进行跨域请求，网页内容脚本不适合作为模型请求入口。[Chrome 跨域请求说明](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

DeepSeek 提供 Anthropic 格式兼容地址 `https://api.deepseek.com/anthropic`，支持 `x-api-key` 和工具输入 Schema，适合返回受约束的字段来源候选。首轮按用户指定使用该格式实测。[DeepSeek 官方兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/)

“本地存储”与“使用远程模型”同时成立：模型请求会将用户确认过的最少字段描述发送给提供商，因此产品说明不能再写“插件绝不联网”或“任何信息都不离开本机”。

## 2. P0 的使用流程

1. 用户导入简历，维护补充资料并保存。
2. 在“模型设置”选择接口格式、提供商地址、模型名称，配置自己的 Key，点击“连接并测试”。用户只给该提供商域名授权。未配置模型时仍可完整使用本地资料与规则填写。
3. 扫描招聘网页，先展示本地规则结果；对名称陌生、含义不明确的字段提供“用模型辅助匹配”。
4. 用户查看本次目标地址、模型及将发送的字段名称、分组和来源含义，确认后请求。默认不因打开页面、导入简历、保存资料或普通扫描自动调用模型。
5. 模型返回候选来源及理由，侧边栏展示“模型建议”，供用户选择或修正。单一候选同样不能跳过填写预览。
6. 在本地取得正式资料值，检查分组、经历绑定、控件和现有值，再由用户点击填写。模型失败时保留本地结果和手动选择。

P0 的“模糊字段”指名称变化和有限上下文中的语义识别，例如“您目前落脚的城市”对应现居城市。它不自动补造事实，不从年月生成日期，不代替网站控件适配，也不承担回答润色或 PDF 解析。真正无法区分的字段可以返回歧义或未匹配。

## 3. 多提供商支持

实现统一的 `ModelFieldMatcher`，底层提供 Anthropic Messages 和 OpenAI Chat Completions 两个协议适配器。两者都实现请求组装、认证、响应读取和统一结果校验；首轮真实基线用 DeepSeek，两种格式分别验证。其他提供商可配置兼容地址和模型名，只有实际通过连接与字段样本的组合才列为已验证。

| 配置 | 首版行为 |
| --- | --- |
| 接口格式 | Anthropic Messages / OpenAI Chat Completions |
| Base URL | HTTPS 提供商基础地址，允许受支持的路径前缀；校验后端点拼接，不重复 `/v1` |
| 模型名 | 用户配置，不从提供商名称猜测；报告记录请求名与提供商返回名 |
| API Key | 用户自己的密钥，绑定配置地址与协议，不随更换提供商自动携带 |
| 连接测试 | 一次小请求，检查认证、响应格式和模型实际可用；不发送真实简历 |
| 能力 | 标记工具格式或 JSON 输出支持情况；不把某一家专用参数发送给所有兼容服务 |

Anthropic 适配器优先以强制工具返回结构化结果；这只是数据返回容器，不执行模型工具。OpenAI 适配器按提供商能力使用结构化或 JSON 输出，再做本地严格校验。DeepSeek 的思考模式配置限于其适配配置，其他服务按实际能力处理。

首版同时保存一套当前模型配置即可；切换配置会取消在途请求、增加配置修订并使相关建议失效。地址、协议变化必须重新输入 Key 并测试。多模型同时投票、自动故障切换和跨提供商重试继续后置。

## 4. 本机环境变量与插件 Key

本机已在 `~/.bashrc` 配置 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。开发脚本可读取这些配置，测试仅在内存中传递 Key，不写入源码、构建产物、报告、截图或打包文件。

普通浏览器扩展没有直接读取操作系统环境变量的接口，不能依赖 `process.env` 取得安装者的 Key；构建时注入会把 Key 带进安装包。若通过原生消息读取本机配置，需要另外安装并注册本地程序，这不符合本项目的纯插件目标。[Chrome 原生消息说明](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

正式产品由用户在可信插件设置页输入 Key。建议默认仅保存于 `chrome.storage.session`，用户可明确选择“在本机记住”后存入 `chrome.storage.local`；两种区域均限制为 `TRUSTED_CONTEXTS`，不用 `storage.sync`。本地持久化不宣称是加密保险箱；首版也不以把解密密钥和密文一起存储来声称解决了这个问题。[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)

完整资料备份可包含协议、地址和模型名，不包含模型 Key，也不包含旧服务凭证。备份恢复后模型辅助默认未启用，需重新配置 Key、授权并测试。清除模型设置只清理模型凭证、配置及相关权限，不调用旧版会连带清除简历的断开连接流程。卸载或清除全部资料的影响在对应操作中说明。

每个试用者使用自己的 Key。共享安装包不嵌入开发测试 Key，也不依靠“混淆代码”保护共用密钥。

## 5. 权限、网络和生命周期

发布包保留 `activeTab`、`scripting`、`storage`、`sidePanel`。为支持自选 HTTPS 提供商，保留 `optional_host_permissions: ["https://*/*"]` 的可申请范围；只有用户点击连接某一地址时，申请该目标主机权限，不自动获得所有网站的权限。CSP 允许所需 HTTPS 连接；同时由应用层限制请求只能前往当前用户配置、验证并授权的地址。

移除历史账号同步和后端访问入口、loopback 连接权限及旧请求代码；清理旧来源授权时保留当前模型配置确实仍需的权限。按 origin 申请权限不能表达精确路径限制，因此应用层另外校验协议、主机、端口及 API 路径。

由侧边栏的可信扩展页面执行模型请求，后台负责配置、可信消息和权限等短操作。招聘网页及其内容脚本不能读取 Key、发起任意 URL 请求或触发模型调用；只接收本次用户确认填写所需的值。侧边栏关闭、页面导航、重新扫描、用户修改来源选择、正式资料变化或模型配置变化，取消并丢弃相应在途结果。

建议每次最多 20 个目标字段，描述与来源目录合计不超过 32 KiB，每次最多 2000 输出 token、单次请求 30 秒、总操作预算 45 秒，同一会话只允许一个在途模型任务。用非流式响应实现首版。响应最多 64 KiB，读取过程有大小和时间上限；不能先无限读取再校验。

使用 HTTPS、禁止重定向、不带网页 Cookie。拒绝带用户信息或查询密钥的 URL，地址只能在可信设置页修改。超时、限流、认证和网络错误不自动重试；只有输出格式无效时，可在剩余预算内最多修正重试一次。不给另一个提供商自动发送内容。

## 6. 发送内容与结果约束

默认只发送有待识别的字段标签、必要的分组含义、控件类型/选项，以及候选资料的名称与语义说明。移除真实资料值、网页已有输入、整页 DOM、完整 URL、Cookie 和其他凭证。内部经历 ID、请求号和来源引用映射为本次临时代号；学校和公司名称不作为区分经历的捷径，多段经历在本地绑定。

名称、说明、分组和选项本身也可能包含个人信息或恶意指令，因此发送前进行限长与过滤并提供实际内容预览；用户能取消、排除或修改。无法安全表达的描述保留手动选择。将网页文字视作待分类数据，不接受其中要求上传简历、修改系统规则或调用工具的指令。

请求和结果使用 `FieldMatcher` 统一契约，并额外关联模型配置修订、用户来源选择修订和发送内容修订；任何变化都使旧建议失效。模型只返回允许的字段与来源代号、状态和简短理由。运行时严格校验未知属性、越界引用、重复字段、歧义数量、受限字段、分组和经历归属。返回自由生成的真实值或可执行内容不可转为填写操作。

一个模型声称“很有把握”不能越过规则限制。含义有歧义时继续手选；填入前仍须本地值解析、控件匹配、当前值核对和用户确认。取消、失效或失败不清空已有本地匹配和资料。

## 7. 本次可行性实测

2026-09-11 在独立 Google Chrome for Testing 配置中加载最小 Manifest V3 扩展，由 `chrome-extension://` 页面真实 `fetch` DeepSeek HTTPS 接口。Key 从本机配置读入测试进程后仅在内存中传递；扩展目录、临时浏览器配置在结束时清理。没有启动业务后端，没有发送个人简历，也没有对招聘网站执行填写。

| 请求 | HTTP 状态 | 单次用时 | 合成字段结果 |
| --- | --- | --- | --- |
| Anthropic Messages | 200 | 约 1.36 秒 | 10/10 与预期一致 |
| OpenAI Chat Completions | 200 | 约 1.24 秒 | 10/10 与预期一致 |

样本包括陌生表达的现居城市、期望工作地点、生源地、户籍、学校、学历/学位，以及应保留歧义的联系方式、受限字段和没有对应资料的紧急联系人。两次调用的字段集合相同，共 10 个不同案例，不能称为 20 个独立样本或真实网站兼容率。

证据：[脱敏实测报告](../artifacts/extension-model-direct-probe.json)、[可复现脚本](../scripts/probe-extension-model.mjs)。脚本是主动执行才联网的可行性探针，不属于常规离线测试或发布包；支持从进程环境读取 Key，也可解析本机已知 `.bashrc` 的相关字面量赋值，不执行其中 shell 命令。

两次请求的配置模型名均为本机的 `deepseek-v4-flash`，Anthropic 响应返回同名，OpenAI 响应返回 `deepseek-flash`。如实保留两者，不假定别名在不同协议或不同日期永远对应相同模型。

本次使用测试扩展预先声明目标主机权限，验证的是扩展页面直连能力与小规模语义匹配。产品的动态授权 UI、Key 管理、网络失败、发送内容过滤、响应大小限制、取消和真实表单效果仍需按场景 G01–G12 验收。

复现会再次产生少量模型调用，使用本机已安装的测试浏览器时可执行：

```sh
RESUME_TEST_BROWSER='/path/to/chrome' node scripts/probe-extension-model.mjs
```
