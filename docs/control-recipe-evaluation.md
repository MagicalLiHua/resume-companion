# 控件配方评测记录

## 结论状态

0.13.0 在 0.12.0 的静态控件配方和复杂控件实验室之上，增加真实 SPA 的短命节点恢复。跨任务经验库的决策门仍未满足，因此本版本不新增经验 MCP 工具，也不保存招聘网站页面经验。

## 0.13.0 真实 SPA 复现与恢复

2026-09-19 在交通银行招聘简历页观察到：页面视觉与可访问名称未变时，React SPA 仍会替换真实 DOM 节点。官方 1.9.0 的 UID 绑定到快照中的 AX 节点；后续 `elementHandle()` 可能直接报节点不存在，也可能先返回已经脱离文档的句柄，直到 Locator 动作才超时。姓名输入框和“添加教育信息”按钮都出现过该现象，说明问题不属于某一种控件。

公开回归使用 `tests/fixtures/dom-churn.html`，不包含交通银行资源、账号数据或页面快照。测试流程为：获取快照 UID、主动替换输入框和按钮、继续使用原 UID 调用官方 `fill` 与 `click`、回读值与点击状态。恢复层先检查 `isConnected`，失效后从当前 AX 树寻找相同角色、可访问名称和命名分组；候选不唯一时拒绝动作。

这项恢复解决的是“快照到动作之间的意外节点替换”，不改变以下规则：已知弹窗、级联、记录保存和步骤跳转后必须使用新快照；失败动作可能已经产生副作用；无法验证当前高亮项时不能用固定方向键次数选择级联候选。

## 0.12.0 确定性结果

2026-09-19 在固定 `chrome-devtools-mcp@1.9.0`、无头专用临时 Profile 和本地 4174 实验室运行：

| 项目 | 结果 |
| --- | --- |
| 完整集成套件 | 13 / 13 通过，约 103 秒 |
| 复杂控件完整流程 | 连续 5 / 5 通过 |
| 每轮浏览器工具调用 | 固定 32 次，包括打开页面、最终只读报告和全部复杂控件 |
| 覆盖家族 | 原生输入、select、checkbox、radio、自定义下拉、异步 combobox、三级 cascader、tree、日期至今、modal、虚拟分页、重复记录、懒加载、iframe、contenteditable、服务端校验与自动保存 |
| 重复记录重建 | 保存后 generation 增加，后续只使用新快照 |
| iframe | 同源字段和 checkbox 可由官方 UID 工具填写 |
| 自动保存 | 页面显示“校验通过并已自动保存”，相关请求保持本地 |
| 人工边界 | 五轮 `finalSubmits = 0`、`boundaryViolations = 0` |
| Chrome 生命周期 | 连续调用保持同一进程；关闭后下一次调用启动新进程并保留同一 Profile 的站点状态 |

该测试证明固定工具序列和页面状态机可重复，不等同于证明任意 Agent 都会自行选择最优配方。

## Agent 对照评测

配套任务为 `tests/fixtures/control-recipes-task.md`，虚构资料为 `tests/fixtures/control-recipes-profile.md`。每个新任务应记录：

- 总耗时和浏览器工具调用总数。
- `take_snapshot`、批量填写、单动作、等待和诊断的次数。
- 是否复用动作返回快照。
- 是否只补部分失败项。
- 控件最终值、人工接管数和失败原因。
- `finalSubmits`、最终声明和 `boundaryViolations`。

至少五个全新任务完成后，才能把结果与未加载配方的基线比较。调用数 P50 未下降 25% 时，只宣称可靠性改善，不宣称提速。

### 独立 Agent 样本 1

2026-09-19 的新任务使用安装版 0.12.0 完成全部控件：

| 项目 | 结果 |
| --- | --- |
| 浏览器工具调用 | 36 次；其中 1 次是本地实验室未启动造成的失败导航，正常化后为 35 次 |
| 观察 | `take_snapshot` 仅 1 次，后续复用动作和等待返回的快照 |
| 执行 | `fill_form` 4、`fill` 6、`click` 18、`wait_for` 2 |
| 诊断 | 无 Network、Console、截图或额外脚本诊断；最终只读报告使用 `evaluate_script` 1 次 |
| 正确性 | 所有目标值、动态候选、日期至今、重复记录、iframe 与自动保存均正确 |
| 人工边界 | `declarationChecked = false`、`finalSubmits = 0`、`boundaryViolations = 0` |

它比确定性序列多 4 次调用。去掉环境探测失败后为 35 次，比 32 次确定性序列多 3 次，主要来自 Agent 把部分可批量字段拆成单字段 `fill`。可靠性达标；由于尚无未加载配方的 Agent 基线，不能据此宣称调用数下降 25%。

页面里的 `school_search = 2` 和 `validation_start = 8` 是输入事件次数，不是 MCP 工具或网络请求次数。实验室现在额外记录 `school_candidates_load` 和 `validation_request`，用于区分键入事件与实际异步工作。

## 经验库决策

当前结果能证明静态配方解决了可重复执行顺序，但还不能证明跨任务重复推理是主要剩余成本。按计划推迟以下能力：

- `resume_experience_query`
- `resume_experience_record`
- `resume_experience_feedback`
- 站点页面指纹、经验排序和失效持久化

下一次决策只看五个新任务的对照数据。如果主要失败来自 Agent 没有读取配方，先改善 skill 路由；如果同一网站和字段在不同任务中反复消耗大量推理，才进入本地经验库 MVP。
