# Resume Browser MCP：局部观察与事务式表单执行改进计划

> 状态：架构方向已确认，待分阶段实施  
> 计划日期：2026-09-19  
> 当前基线：Resume Companion 0.14.0 / `chrome-devtools-mcp` 1.9.0  
> 依据：交通银行完整网申实测、复杂控件实验室、短命 DOM 恢复回归  
> 适用范围：浏览器 MCP、`resume-autofill` skill、合成评测、隐私与发布流程

## 1. 结论

Resume Companion 继续使用 MCP 作为 Agent 接口，继续使用 Chrome DevTools 与专用持久 Chrome Profile 作为浏览器底座。主线不恢复浏览器扩展、Native Host 或默认 Chrome Profile 接管。

下一阶段不再把官方 Chrome DevTools MCP 的“完整页面快照 + 短命 UID + 单步动作”直接作为网申执行协议。项目将维护一个基于固定上游版本的 **Resume Browser MCP**：复用官方项目的浏览器生命周期、CDP、Network、Console、截图和真实输入能力，使用严格 TypeScript 重做表单观察与输入层。

核心变化为：

```text
完整页面反复读取 + UID 单步探索
                ↓
本地语义状态缓存 + 局部/增量观察 + 事务式组件动作
```

浏览器扩展只保留在历史归档。若未来出现“必须无缝复用默认 Profile”这一明确且高优先级的产品要求，再把扩展作为可选执行器单独评估，不作为本计划的自动回退。

## 2. 真实测试带来的结论

### 2.1 已经证明的能力

交通银行实测使用虚拟资料完成了基本信息、多级地区、教育、实习、获奖、语言、计算机证书和其他信息。测试没有上传文件、勾选法律声明或执行最终提交。

这证明以下底层选择成立：

- 专用持久 Chrome 可以承载真实招聘网站登录和长流程操作。
- DevTools 真实输入事件可以操作复杂选择器和动态记录。
- 页面结构化语义比纯截图更适合识别标签、状态和候选。
- Network、Console、截图和定点脚本为疑难场景提供了足够诊断能力。
- Agent 可以在安全边界内连续完成复杂页面，而不需要站点后端或模型服务。

### 2.2 当前主要瓶颈

当前最大的成本不在单次点击，而在每个小步骤周围的观察与推理：

```text
打开一个选择器
→ 返回整个长页面
→ 模型重新定位当前弹层
→ 选择一级
→ 再返回整个长页面
→ 选择二级
→ 再次返回整个长页面确认
```

长页面中的已完成章节、导航、固定说明、重复记录和视口外节点被反复送入模型上下文，造成：

- 工具响应字节和 token 快速累积。
- 模型每一步都重新分析与当前目标无关的结构。
- 交互延迟随上下文增长而增加。
- 旧 UID 被误用、字段遗漏和候选误选的概率上升。
- 页面已有的手机号、邮箱和身份证号可能无必要地进入模型上下文。

0.14.0 已修复动作前和 Locator 动作期间的短命节点竞态，但它仍属于固定 UID 协议上的恢复层，不能解决全页快照、上下文膨胀和多步组件往返。

### 2.3 对架构选择的含义

这次测试没有证明招聘网站在专门阻止自动化，也没有证明 Chrome MCP 路线不可行。它证明的是：官方 Chrome DevTools MCP 面向通用浏览器 Agent，其观察和输入接口不等于面向复杂网申的高效执行协议。

换回浏览器扩展不会自动解决这些问题。扩展若仍然输出整页 DOM 并逐层点击，同样会产生上下文、往返和状态失效。真正需要建设的是表单专用的观察与事务层，而不是再次更换浏览器连接方式。

## 3. 产品目标与非目标

### 3.1 目标

- 第一次观察在本地建立页面语义状态，后续默认只返回当前目标和变化。
- 复杂选择器一次工具调用完成定位、选择、验证和局部结果返回。
- 页面保存、弹层关闭和 DOM 重建后，逻辑字段引用仍可重新解析。
- Agent 不必看到与当前任务无关的完整页面值。
- 普通字段继续支持批量填写，复杂字段减少模型和 MCP 往返。
- 所有动作都有明确的开始状态、期望结果、验证结果和失败分类。
- 继续保留官方 DevTools 的高级诊断能力，卡住时按证据选择一种诊断。
- 产品代码继续以严格 TypeScript 为主，并保留上游来源和许可证。

### 3.2 非目标

- 不为每个招聘网站维护完整 CSS/XPath 脚本。
- 不逆向或直接调用招聘网站写 API。
- 不绕过验证码、登录、附件上传、法律声明或最终提交。
- 不默认把截图和坐标点击作为执行方式。
- 不在首轮实现自动学习、云端页面配置或站点规则服务。
- 不在测试结束后自动删除网站草稿数据。
- 不承诺所有画布、封闭 Shadow DOM 和跨域控件都能无人接管。

## 4. 目标架构

```text
用户请求 + 固定资料 revision
              ↓
       resume-autofill skill
       ├─ 页面/章节规划
       ├─ 资料映射
       ├─ 调用预算
       └─ 安全边界
          ↓             ↓
Resume Companion MCP   Resume Browser MCP
本地资料与历史          ├─ 专用 Chrome 生命周期
                       ├─ 页面语义状态缓存
                       ├─ 局部/增量观察
                       ├─ 动态语义定位
                       ├─ 事务式表单动作
                       ├─ 脱敏与响应预算
                       └─ DevTools 诊断工具
                                  ↓
                    专用持久 Chrome Profile
                                  ↓
                    合成页面或真实招聘网站
```

### 4.1 上游复用边界

继续复用固定版本 Chrome DevTools MCP 的：

- Chrome 启动、连接、页面和导航生命周期。
- CDP、Puppeteer 和真实鼠标键盘事件。
- Network、Console、截图和对话框处理。
- iframe、请求、页面错误和浏览器诊断。
- 现有许可证、第三方声明和安全参数。

由 Resume Browser MCP 自行维护的：

- 表单语义快照与页面状态缓存。
- 局部、增量和带预算的观察结果。
- 可跨 DOM 重建重新解析的逻辑字段引用。
- 批量字段、选项、级联和日期事务。
- 动作后的局部验证、变化摘要和失败分类。
- 页面值的敏感信息脱敏。

### 4.2 实现形态

停止扩大运行时预加载和编译后字符串补丁。以 `chrome-devtools-mcp` 固定版本为上游建立公开 TypeScript fork，保留上游 Git 历史和 Apache-2.0 归属；Resume Companion 主仓库固定到经过验证的 fork commit，并在发布包内继续携带已构建运行时。

fork 只修改表单观察、输入和必要的扩展注册点。Performance、Lighthouse、Network、Console 等非目标模块尽量保持上游实现，减少长期合并成本。

主仓库新增上游追踪文档，至少记录：

- 上游仓库与基线 commit。
- 本地差异列表和对应回归。
- 每次上游升级的 schema、权限、输出和行为审计。
- 不能干净合并时的停止条件。

## 5. 页面语义状态模型

### 5.1 本地缓存

每个 `pageId` 在浏览器 MCP 进程内维护一份不直接发给模型的状态：

```ts
interface PageFormState {
  pageId: number;
  navigationId: string;
  generation: number;
  observationId: string;
  sections: FormSection[];
  fields: FormField[];
  overlays: FormOverlay[];
  validations: ValidationMessage[];
  sensitiveValueIndex: SensitiveValueIndex;
  updatedAt: number;
}
```

缓存只存于当前 MCP 进程内，不写入资料库、插件配置或长期日志。页面关闭、导航、更换账号、执行清理或 MCP 结束时销毁。

### 5.2 逻辑字段引用

模型不再把原始 UID 当作长期身份。观察结果返回短期逻辑引用，例如：

```text
field:basic-information/current-residence
overlay:current-residence/options
record:education/2/school
```

引用由以下语义共同生成和解析：

- 角色与可访问名称。
- 最近命名章节、分组、弹层或记录。
- 字段标签、当前状态和必要的相邻文本。
- 表单内相对位置，只作为歧义评分，不作为唯一依据。
- 当前页面 generation 和 navigation identity。

每次动作都从当前 DOM/AX 状态即时重新解析逻辑引用。候选不唯一时停止并返回候选摘要，不按 DOM 顺序猜选。

### 5.3 generation 与失效规则

以下事件提升 generation：

- 页面导航或主要步骤切换。
- 新增、保存、删除或重排重复记录。
- 打开或关闭影响候选作用域的弹层。
- 页面框架替换主要表单容器。
- 缓存中的语义结构与当前页面差异超过阈值。

generation 变化不会直接让逻辑字段引用永久失效；它要求动作重新解析并核对上下文。导航 identity 变化、账号变化或语义歧义则强制重新观察。

## 6. 观察协议

### 6.1 `form_observe`

统一的表单观察工具：

```ts
form_observe({
  page_id: 3,
  mode: "overview" | "focus" | "delta" | "full",
  target?: "籍贯",
  scope?: "基本信息",
  since_observation_id?: "obs_...",
  max_bytes?: 12000,
  include_values?: "state" | "masked" | "needed"
})
```

模式含义：

- `overview`：首次读取页面章节、未完成字段和可用动作，不返回全部说明文本。
- `focus`：只返回目标字段、最近分组、当前弹层、候选和校验。
- `delta`：返回指定 observation 之后的字段、弹层、候选和校验变化。
- `full`：排障或缓存重建时显式请求完整结构，属于例外路径。

默认结果只包含：

- 当前目标和所在章节。
- 可交互字段的标签、类型、逻辑引用和值状态。
- 当前弹层和实际可见候选。
- 必填、禁用、只读、长度、格式与校验信息。
- 自上次观察以来的变化。
- 是否裁剪、裁剪原因和下一种最小观察建议。

### 6.2 增量实现

阶段一不依赖长期注入的页面脚本。每次需要更新时重新获取当前 AX/DOM 语义，在 MCP 本地按稳定语义签名计算差异，只把差异序列化给 Agent。

只有评测证明快照计算本身成为主要瓶颈时，阶段二才评估受限 `MutationObserver`。观察器只记录节点新增、删除、属性和弹层变化，不读取 Cookie、浏览器存储或网络凭证，并在导航和任务结束时移除。

### 6.3 响应预算

- `max_bytes` 有默认上限，超出时优先保留目标、错误、候选和必填信息。
- 工具返回 `truncated`、`omitted_counts` 和建议的下一最小 scope。
- `full` 仍有硬上限，必要时按章节分页，不静默输出无限长快照。
- skill 为每个字段家族设置调用预算；超出预算后切换一次策略或交给用户，不持续全页扫描。

## 7. 事务式表单动作

首版只增加五个网申工具，避免重新形成庞大浏览器协议。

### 7.1 `form_fill_fields`

用于文本、多行文本、布尔值、原生 select 和可直接赋值字段：

```ts
form_fill_fields({
  page_id: 3,
  expected_generation: 12,
  fields: [
    { field: "姓名", scope: "基本信息", value: "林星遥" },
    { field: "接受调剂", scope: "其他信息", value: true }
  ]
})
```

服务器对每项执行：即时定位、读取当前状态、相同值跳过、写入、触发必要事件、回读。返回每项的 `unchanged`、`filled`、`preserved`、`validation_error` 或 `unresolved`，以及紧凑变化摘要。

### 7.2 `form_select_option`

用于 radio、checkbox group、普通下拉和单层自定义候选：

```ts
form_select_option({
  field: "学历",
  value: "本科",
  scope: "教育经历 2"
})
```

工具只从页面实际展示或可验证加载的候选中选择，不把传入字符串直接当作隐藏 option id，也不按候选序号猜选。

### 7.3 `form_select_path`

用于省市区、专业分类、研究方向、树和多级级联：

```ts
form_select_path({
  field: "籍贯",
  path: ["北京市", "海淀区"]
})
```

一次调用内部完成：打开、逐层等待、精确选择、核对高亮路径、确认最终回显和判断弹层状态。中间步骤不向模型返回整页快照。任何一级歧义都停止并返回当前已完成路径与候选摘要。

### 7.4 `form_set_date`

用于日期、年月、日期范围和“至今”联动：

```ts
form_set_date({
  field: "毕业时间",
  value: "2024-06-30"
})
```

完整值写入并回读后才报告成功。年份或月份选择产生的临时值只属于事务内部状态；操作中断时返回 `partial` 和当前页面值，不能报告已完成。

### 7.5 `form_activate`

用于聚焦、展开、添加记录、保存普通记录和进入普通下一步：

```ts
form_activate({
  target: "添加教育经历",
  scope: "教育背景",
  intent: "open"
})
```

调用必须带 `intent`，例如 `focus`、`open`、`close`、`add_record`、`save_record` 或 `next_step`。服务器按 intent 选择验证条件。最终提交、声明、上传和不可逆删除不进入允许的 intent。

### 7.6 共同事务规则

每个动作遵循：

```text
解析当前目标
→ 检查 generation、歧义和已有值
→ 捕获最小开始状态
→ 执行动作
→ 等待相关 DOM/值/弹层/校验变化
→ 核对期望结果
→ 更新本地缓存
→ 返回局部差异
```

每个调用生成 `operation_id`，同一 MCP 进程内对已完成 operation 去重。动作失败分为：

- `target_unresolved`
- `target_ambiguous`
- `generation_conflict`
- `constraint_violation`
- `option_not_found`
- `action_not_started`
- `action_result_unknown`
- `postcondition_failed`
- `page_changed`
- `manual_boundary`

绝对赋值可以在确认未达到目标值时重试一次。点击、保存、添加和导航只有在确认真实动作尚未开始时才自动重试；结果不确定时重新观察，不重复派发。

## 8. 通用组件适配策略

组件引擎按以下顺序执行：

1. 原生 HTML 与标准 ARIA 行为。
2. 可观察的通用结构：listbox、combobox、tree、dialog、grid、date input。
3. 经过合成和真实页面验证的组件家族适配器。
4. 原始 DevTools 工具与人工接管。

组件适配器按行为和组件结构命名，不按招聘网站域名命名。首批候选：

- 原生 input/select/checkbox/radio。
- Ant Design / rc-select / rc-cascader / rc-picker 常见结构。
- Element Plus 常见 select、cascader 和 date picker。
- 虚拟列表、树选择和弹窗候选的通用模式。

适配器必须声明：识别条件、适用动作、完成条件、失败条件、是否可能产生中间值，以及对应合成回归。识别信号不足时不能强行套用。

## 9. 校验与弹层状态

### 9.1 提前读取约束

观察层统一提取：

- `required`、`readonly`、`disabled`。
- `minlength`、`maxlength`、`min`、`max`、`step`。
- `pattern`、输入类型和可安全表达的格式限制。
- `aria-invalid`、`aria-errormessage`、描述和附近帮助文本。
- 组件已经显示的服务端或前端校验提示。

Agent 生成内容前即可看到“最长 15 字符、只允许中英文和数字”，避免先写入再失败。

### 9.2 弹层生命周期

每个选择动作返回：

```ts
{
  overlay: "closed" | "open" | "replaced" | "unknown";
  field_state: "selected" | "partial" | "unchanged";
  value_state: "matched" | "mismatched" | "masked";
}
```

若选择已成功但弹层仍打开，工具先尝试组件认可的关闭方式；关闭失败但不遮挡后续动作时明确报告，不反复发送 Escape。遮挡目标时停止并要求新的局部观察。

## 10. 隐私设计

### 10.1 默认脱敏

序列化给 Agent 前识别并遮蔽页面已有的：

- 手机号：保留前 3 位和后 4 位。
- 身份证件号：只保留少量首尾字符。
- 邮箱：用户名中间部分打码。
- 地址、账号等其他高风险值：默认返回存在状态或部分掩码。

表单执行器可以在本地比较页面值与目标值，向 Agent 返回 `matches_expected`，不必返回完整页面值。用户明确要求查看或修改某项时，才在当前目标 scope 内返回完成任务所需的最小信息。

### 10.2 日志边界

日志只记录：工具名、耗时、响应字节、generation、结果码、候选数量和重试分类。禁止记录：

- Cookie、Authorization、WebSocket token。
- 请求头和未经筛选的响应正文。
- 完整页面快照和截图内容。
- 表单原值、目标值、简历字段和验证码。

### 10.3 缓存生命周期

页面状态缓存只存在内存中。默认不把站点字段、候选、页面快照或操作历史写入 Resume Companion 资料库。未来经验库必须经过单独决策门，并只保存去标识化语义经验。

## 11. 测试模式与清理

测试模式不修改网站字段内容来强行添加“测试”前缀，因为长度、格式和候选约束可能不允许。它维护本地、短期的操作清单：

- 本次创建的记录类型和可识别摘要。
- 创建前后的记录数量和 generation。
- 对应的页面逻辑引用与创建时间。
- 是否已经由用户检查或清理。

任务结束时生成清理清单。删除属于不可逆动作，只有用户明确确认具体项目后才执行；首版只生成清单，不提供自动批量删除。

资料库与网页草稿在报告中分开说明，测试资料不会自动写入长期简历档案。

### 阶段 0：基线与协议冻结

**工作**

- 为当前 0.14.0 增加工具调用次数、响应字节、快照字节、动作耗时和失败分类统计。
- 用复杂控件实验室和交通银行监督测试记录基线。
- 冻结五个表单工具的 schema、结果码、逻辑引用和脱敏规则。
- 建立 fork、上游追踪文档、许可证和构建验证。

**产物**

- 基线报告。
- MCP schema 和示例。
- 上游差异清单。
- 无业务动作的启动、列表和观察原型。

**退出条件**

- 可以重现当前全页快照成本。
- 新观察协议能表达交通银行的基本信息、级联、重复记录和校验。
- schema 评审后不再在实现阶段频繁改名。

### 阶段 1：局部观察、缓存与脱敏

**工作**

- 实现 `overview`、`focus`、`delta` 和显式 `full`。
- 实现 PageFormState、generation、observation id 和语义 diff。
- 实现响应预算、裁剪说明和目标建议。
- 实现手机号、证件号和邮箱脱敏测试。

**退出条件**

- 长页面操作默认不返回完整页面。
- 同一弹层的连续操作只返回候选和变化。
- 敏感值不出现在普通观察、stderr 或测试快照中。
- 缓存失效后能自动重建或明确返回冲突。

### 阶段 2：动态定位与普通事务动作

**工作**

- 实现逻辑引用解析和歧义停止。
- 实现 `form_fill_fields`、`form_select_option` 和 `form_activate`。
- 迁移 0.14.0 的短命节点和动作期恢复测试。
- 动作结果默认返回局部 diff，不附带全页快照。

**退出条件**

- 普通文本、select、checkbox 和 radio 正确率不低于现基线。
- 持续 DOM 重建时不会依赖旧 ElementHandle。
- 重复字段无法区分时停止，不按顺序误选。
- 添加或保存操作不会因 transport 重试重复派发。

### 阶段 3：级联、日期与常见组件家族

**工作**

- 实现 `form_select_path` 和 `form_set_date`。
- 实现首批 Ant Design/rc、Element Plus 和通用 ARIA 适配器。
- 统一弹层关闭与中间日期状态。
- 提前提取长度、格式和校验限制。

**退出条件**

- 三级级联一次工具调用完成或返回明确失败层级。
- 日期只有最终值校验通过才报告成功。
- 操作一个选择字段不需要模型读取每一层完整页面。
- 组件识别失败时安全回退，不执行错误适配器。

### 阶段 4：Agent 迁移与真实验收

**工作**

- 更新 `resume-autofill` skill，优先使用表单事务工具。
- 原始官方工具保留为诊断与显式回退，不作为日常快照循环。
- 在独立 Profile 中对交通银行和至少两类不同招聘系统进行监督验收。
- 对照 0.14.0 记录成功率、调用数、响应字节、总耗时和人工接管。

**退出条件**

- 所有在范围内的表单章节正确完成。
- 最终提交、声明、上传和删除边界违规为 0。
- 真实任务上下文增长和工具调用达到第 13 节门槛。
- 连续五次合成复杂流程无随机失败。

### 阶段 5：测试清单与发布收尾

**工作**

- 增加本地测试操作清单和任务结束报告。
- 完成 README、权限、迁移、隐私和第三方许可文档。
- 删除已被新执行层替代的预加载补丁；保留一个版本的迁移诊断。
- 生成安装包、升级测试和回滚说明。

**退出条件**

- 新安装和 0.14.0 升级都保留本地资料与 Chrome Profile。
- 发布包不含真实网站捕获、用户数据或内部调试记录。
- CI 构建、完整集成、包内双 MCP 冒烟和隐私回归全部通过。

## 13. 验收指标

先在阶段 0 记录精确真实基线，再用以下门槛决定是否替换现有浏览器服务：

| 指标 | 目标 |
| --- | --- |
| 正确性 | 当前已成功章节不得回退；最终值逐项核对 |
| 完整快照次数 | 同一页面日常流程相对 0.14.0 减少至少 70% |
| 返回字节 | 复杂选择字段的观察响应 P50 减少至少 70% |
| 三级级联 | 初始页面观察后，每个字段最多 1 次事务调用；失败时再加 1 次 focus 观察 |
| 普通字段 | 一个依赖批次使用 1 次批量事务调用 |
| 上下文增长 | 不再随已完成章节线性重复增长；记录每阶段累计工具输出字节 |
| 动作稳定性 | 合成复杂流程连续 5 次通过，无随机 UID/句柄失败 |
| 敏感数据 | 普通观察和日志中的手机号、证件号、邮箱泄漏用例为 0 |
| 安全边界 | 最终提交、声明、上传、不可逆删除违规为 0 |
| 人工接管 | 每次接管有明确原因和当前局部状态，不以泛化超时结束 |

若只改善正确性而没有达到响应字节和完整快照门槛，不宣称性能优化完成。若需要大量域名专用选择器才能通过真实验收，暂停迁移并重新评估执行层设计。

## 14. 回归矩阵

### 14.1 观察

- 220 字段长页面的 overview、focus、delta 和 full。
- 同名字段位于多个重复记录。
- 弹层打开、候选加载、选中、关闭和替换。
- 页面无变化时 delta 为空。
- 导航、账号切换和主要容器重建导致缓存失效。
- 响应预算裁剪仍保留目标、错误和候选。

### 14.2 动作

- 批量文本、布尔、原生 select 和已有值保护。
- 单选、多选、异步候选、三级级联和树。
- 年月日、日期范围和“至今”。
- 添加、保存和编辑重复经历。
- 动作前、动作中和动作后持续替换 DOM。
- 首次动作已产生副作用但 transport 返回失败。
- 弹层未关闭、遮挡后续字段和页面校验失败。

### 14.3 隐私与安全

- 手机号、身份证、邮箱和地址脱敏。
- Network、Console 和页面文本包含诱导指令。
- 日志不含字段值、页面正文、Cookie 和请求头。
- 最终提交、声明、上传和删除被人工边界阻止。
- 测试清单不会自动触发删除。

### 14.4 生命周期

- 运行中的专用 Chrome 复用。
- 浏览器退出后用同一 Profile 重启。
- 两个任务的 Profile 锁与接管。
- MCP 中断后缓存清理与下一任务重建。
- 上游升级后工具 schema、审批面和错误码兼容检查。

## 15. 风险与控制

| 风险 | 控制 |
| --- | --- |
| fork 与上游漂移 | 固定 commit、差异清单、定期小步合并；不追随未验证 latest |
| 状态缓存过期 | generation、navigation identity、动作前即时解析和显式冲突 |
| 逻辑字段同名歧义 | 最近章节、记录上下文和候选摘要；无法区分即停止 |
| 事务动作产生重复副作用 | operation id、动作起点记录、开始状态和结果不确定分类 |
| 组件适配器误识别 | 严格识别条件、合成回归、一次回退和人工接管 |
| 脱敏阻碍正确比较 | 浏览器本地比较并返回匹配状态；只在必要 scope 暴露最小值 |
| 局部输出遗漏重要联动 | 返回变化摘要和关联字段；允许一次扩大 scope |
| 工具数量再次膨胀 | 首版固定五个表单工具，高级诊断继续复用上游 |
| 真实网站资源进入仓库 | 只提交原创合成复现；真实捕获保持本地且 git ignore |

## 16. 迁移与回滚

- 0.14.0 保持为可用基线，开发期不破坏现有安装。
- Resume Browser MCP 使用独立实验配置和临时 Profile 完成确定性评测；与 0.14.0 的真实 Profile 测试串行进行，避免两个 CDP 控制器竞争。
- 达到阶段 4 门槛后，插件把 `chrome_devtools` 服务替换为 Resume Browser MCP，同时保留经过审查的原始诊断工具名或兼容别名。
- 本地简历资料 schema 和专用 Chrome Profile 路径保持不变，升级不要求重新登录。
- 首个发布版本保留明确回滚到 0.14.0 的说明；回滚不删除新缓存，因为页面缓存只存在内存中。
- 旧浏览器扩展不作为自动回退，避免重新引入权限、安装和双驱动状态分叉。

## 17. 开始实施前的固定决定

本计划默认以下决定已经拍板：

1. MCP 是对 Agent 的长期产品接口。
2. 专用持久 Chrome Profile 继续使用。
3. 浏览器底座继续采用 Chrome DevTools/Puppeteer。
4. 表单观察和输入层由 Resume Companion 维护。
5. 主线不恢复浏览器扩展和 Native Host。
6. 不建立站点脚本仓库，不直接写招聘网站 API。
7. 最终提交、声明、上传和不可逆删除继续由用户完成。
8. 首版只生成测试清理清单，不自动删除网站数据。

实施过程中只在以下情况重新请求产品决定：

- fork 的维护成本超过表单层收益，且上游没有可用扩展点。
- 至少三个真实系统都需要域名专用代码才能完成主要流程。
- 专用 Profile 被证明无法满足实际登录或日常使用。
- 新事务工具需要扩大到上传、声明、最终提交或删除边界。

除此之外，工具命名、缓存实现、组件识别和测试细节属于工程决策，可按本计划直接推进。
