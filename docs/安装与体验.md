# 简历随行 0.5.0 · 安装与体验

更新：2026-09-11。浏览器扩展包含多版本简历、Markdown 导入、补充资料、模型辅助匹配、悬浮填写窗口和独立投递记录页；0.5.0 将 Codex 本地桥接扩展为多标签页批量工作流。

## 安装

1. 解压 `artifacts/resume-companion-0.5.0.zip`，把解压目录放到固定位置。
2. 在 Chrome 地址栏打开 `chrome://extensions`，开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择解压目录中的 `extension` 文件夹。
4. 保持开发者模式开启。插件需要普通 HTTP/HTTPS 网页访问权限，以自动显示悬浮入口、识别表单并填写选中内容。
5. 本机开发也可直接加载项目的 `dist` 文件夹。固定该目录，后续更新使用“重新加载”，不要卸载后重装。

如果 Chrome 将“网站访问权限”设为“点击时”，悬浮球不会自动出现。可以允许所有网站，或按自己的需要允许指定招聘网站。特殊浏览器内部页面不运行插件。

已在本机 macOS 的 Chrome for Testing 验证。Edge / Windows 尚未实际复测，真实招聘网站按用户安排稍后试用；参见[本次验收记录](纯插件版实现与验收.md)。

## 准备简历与多个版本

点击工具栏“简历随行”，再打开“我的简历”；或从网站悬浮窗口进入资料页。

- 直接维护姓名、联系信息、教育、工作/实习、项目、技能、证书和固定回答。
- “补充资料”可添加籍贯、生源地、期望工作地点等，也能自定义名称和内容。空值保持未知。
- “保存资料”更新正式版本；编辑草稿会自动保存在本地。重新打开时可恢复草稿，另一窗口需要明确接管。
- 在“当前编辑的简历版本”中切换版本；可以新建空白版本、复制、重命名和删除。每个版本保存自己的资料和补充表，最多 30 份。
- 有未保存的编辑时先保存或处理草稿，再切换编辑版本。网页填写时可选择另一份已保存版本，不会动到编辑中的草稿。

## 从 AI 导入 Markdown

1. 打开“从 AI 导入”，复制完整解析提示词。
2. 在你常用的 AI 中粘贴提示词并上传简历 PDF，或提供简历原文。
3. 把 AI 返回的 Markdown 粘贴到输入区，也可导入 UTF-8 的 `.md` / `.markdown` 文件。
4. 点击“解析并预览”，核对字段、日期、经历归属和新增/修改/删除差异。
5. 修正阻塞问题；对暂不能识别的内容核对提示后保留原文。
6. “应用到编辑区”，再点击“保存资料”。重新导入仅替换当前版本的简历章节，保留手工补充表。

可以从当前资料重新生成 Markdown 编辑，也可以回看历史导入原文。表单修改不会改写历史原文。日期只有年份时不会补造月份，只有年月时不会补造日期中的“日”。

## 模型配置

模型辅助是可选能力，本地资料维护与规则填写无需 Key。

在“模型设置”填写接口格式、提供商 Base URL、模型名和自己的 API Key，点击“连接并测试”。

| 接口格式 | DeepSeek 地址 |
| --- | --- |
| Anthropic Messages | `https://api.deepseek.com/anthropic` |
| OpenAI Chat Completions | `https://api.deepseek.com` |

也可填写其他兼容提供商的 HTTPS 地址和模型名。不同服务的参数与结构化输出能力可能不同，以连接测试和实际字段测试为准。

Key 默认只保留在当前浏览器会话，也可选择“在本机记住”。Key 不进入资料备份和分享安装包。正式插件不读取电脑环境变量；每位使用者在自己的配置页设置 Key。

对陌生字段，点击“用模型辅助匹配”，核对将发送的字段说明后确认请求。模型只建议资料来源，实际值仍从本地已保存简历取出；用户核对后才填写。超时、认证失败或模型无法判断时可以继续手动选择来源。

## 网站悬浮窗口与填写

在可识别的招聘或简历页面，右下角自动出现“简”悬浮球。

1. 点击悬浮球，展开右下角窗口。
2. 选择“本次填写使用的简历版本”。窗口自动扫描当前页面，展示可填写内容。
3. 多段经历按网页栏目选择对应条目；有陌生字段时可使用模型建议或手动选择。
4. 点击带 ✓ 的“确认填写”，逐项查看回读结果。申请提交由你自己完成。

已有值默认保留，覆盖需要明确选择。导航、资料变化或网页字段变化会使旧预览失效。撤销只尝试恢复当前网页仍符合条件的字段，不能回滚招聘网站已经自动保存的数据。

页面未识别、窗口被网站限制或没有出现悬浮球时，可点击浏览器工具栏图标使用侧边栏。可在“备份与恢复”中关闭自动悬浮入口。

## Codex 批量填写

发布包中的 `codex-plugin` 是自包含运行目录；项目开发源位于 `plugins/resume-companion`。首次安装可让 Codex 内置的 `plugin-creator` 把这个现有目录加入本地 marketplace；开发者更新后使用同一 marketplace 重新安装。Codex 官方也建议在开发阶段通过本地 marketplace 测试插件。在 Codex 安装并启用后：

1. 在扩展“备份与恢复”中开启“Codex 本地桥接”。该开关默认关闭。
2. 把需要处理的网申页面保留在 Chrome 标签页中，不必逐页切到前台。
3. 在新的 Codex 任务中要求列出网申标签页。Codex 只取得普通 HTTP/HTTPS 页面的标题、网址和临时标签页 ID。
4. 选定范围后，Codex 批量扫描最多 20 页，并汇总每页的建议、未知项、受限项和已有值。
5. 核对完整预览并明确确认后，Codex 才能批量填写；随后会批量回读。需要恢复时可要求批量撤销。

页面导航、标签页关闭、表单结构变化或简历版本更新会使对应扫描会话失效。批量操作逐页返回结果，一页失败不会被计作成功。用户填写后继续手改的值不会被撤销覆盖。

本地桥接只监听 `127.0.0.1:43117` 并校验固定扩展来源，但不等同于对恶意本机进程的强隔离。只在可信电脑上、需要 Codex 操作期间开启；用完可关闭。详细工具和边界见[Codex 批量网申能力](Codex网申能力最小验证.md)。

## 投递记录与统计

“投递记录与统计”是独立页面，和资料编辑、模型配置分开。

通过插件扫描过的页面，检测到原生提交动作后会自动留下公司、岗位、网址和记录时间；同一扫描会话去重。能识别的页面成功提示也会作为来源说明保留。记录直接进入列表和统计，不需要“待确认/已确认”操作。

支持按公司、岗位、备注搜索，按进展筛选，编辑、删除和导出 CSV / JSON。统计显示记录岗位数、已识别公司数、面试中和 Offer 数。没有检测到的投递可点击侧栏“记录这次投递”，或在记录页新建。

页面信息是线索，实际提交结果以招聘网站为准。部分网站通过自定义按钮或跨页流程提交，当前可能需要手动补记。

## 备份、升级与恢复

“导出完整备份”包含全部简历版本、补充资料、原文、草稿、上一份、投递记录和非凭证设置，不含模型 Key。完整恢复会替换文件中列出的资料范围；恢复后模型需重新配置 Key。

“导出当前简历 Markdown”用于阅读和继续交给 AI，不是完整备份；手工补充表和其他简历版本请用完整 JSON 备份迁移。本页草稿也可单独导出，在“导入备份”中载入编辑区后再保存。

从旧版 0.3.1 / 0.3.2 更新：先导出旧版 JSON 备份，把新文件覆盖到原来的加载目录，保持开发者模式开启，然后在 `chrome://extensions` 点击本插件的“重新加载”。新插件会迁移本地简历和上一份，并移除旧业务服务器连接凭证。若提示后台仍是旧版本，重新加载插件后重新打开资料页。

新版完整备份不保证能被旧插件读取。如需回退，使用升级前导出的 1.0 JSON；保留新版完整备份以便再次升级。卸载插件会清除其本地数据，因此卸载或换电脑前先导出完整备份。

## 本次边界

- 真实招聘网站按用户安排稍后验收；合成表单通过不代表所有网站兼容。
- 自定义地区级联、部分复杂下拉、文件上传、跨域 iframe、Shadow DOM 内控件等可能需要手动处理。
- 独立使用浏览器扩展时，模型匹配需要联网，但没有业务后端、账号或常驻本地服务依赖。启用 Codex 桥接时会连接本机 `127.0.0.1:43117`，具体见[Codex 批量网申能力](Codex网申能力最小验证.md)。
- 本地保存不等于加密保险箱。原文和资料备份可能包含个人信息，请保存在自己的位置。
