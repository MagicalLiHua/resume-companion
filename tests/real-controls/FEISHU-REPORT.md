# 0.19.0 飞书教育经历

本轮在既有六个语义工具内新增 UD/Formily 标签和记录归属、UD 单选、双输入起止年月；未改造浏览器管理或增加按站点命名的工具。

## 实现与范围

- 依据当前模块与实际记录容器形成“教育经历 / 第1条”等作用域；原站重复 ID 不作为唯一身份。添加入口归模块，添加后观察新记录。
- 普通 UD 文本外壳与带 selector 的固定下拉分开读取；学校文本不会被误回读成空搜索词。候选严格匹配并在失焦后回读。
- UD 起止年月作为 `date_group` 一次执行，分别打开两端确认已选月份；保留范围、已有值、精度和取消检查。
- 当前实现限定已观察的 UD 单选和年月面板。多选、其他日期面板及原站保存行为不计入支持范围。

## 原站验证状态

2026-09-20 完成新版引擎在飞书招聘原站的完整流程。7 次语义调用包含两次观察、新增记录、六项文本批量输入、两项学历选择、一组起止年月。最后在同一记录内检查九项字段仍保留预期值，已有记录通过页面内摘要比较证明未改变。本次原站实际基线 1 条，新增后 2 条、清理后 1 条；与离线样本的两条基线区分。普通字段及复杂控件没有使用底层写入回退；验证采用定点只读脚本，不读取框架私有状态。

该次语义工具耗时合计 5,461 ms，不含页面打开、浏览器升级、定点只读核对、清理及模型思考时间。控件填写阶段没有人工接管；用户预先授权浏览器重启。临时记录在本次新开的验收标签页中创建，完成后刷新丢弃未保存编辑，待异步资料载入后确认记录数量与摘要恢复，未保存或提交。

原站发现并修复 UD 的延迟收起行为：候选已提交，弹层仍在退出，120 ms 后立即验证会误报失败。现在有界等待弹层关闭，再核对值与校验状态。新增 React 反例先在旧实现复现失败，再验证修复通过；关闭期间的值回滚仍被拒绝。

原站脚本已补齐 TMPDIR 继承、显式选页、generation 与 operation ID、整条记录末尾核对及刷新清理。初始与刷新后的表单均需等待学校资料/摘要就绪，不能只凭记录外壳数量判断已加载。TMPDIR 遗漏曾使测试客户端连接另一临时目录的 socket；误启动的空闲测试管理进程已退出。

已安装并运行 `0.19.0+codex.20260920062329`；安装缓存中的 Supervisor bundle 与验收源码构建一致，原站最终验收使用此运行版本。Moka、智联、飞书三个原站页已重新打开。
